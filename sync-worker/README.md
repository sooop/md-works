# md-works 동기화 Worker 배포 안내

이 폴더는 md-works 의 글·글감·코멘트를 여러 기기에서 동기화하는 서버(Cloudflare Worker)입니다.
서버는 본인의 Cloudflare 무료 계정에 직접 배포하며, 암호화된 데이터만 보관합니다.
이 문서는 배포부터 앱 연결, 사용량 확인, 문제 해결까지 순서대로 안내합니다.

## 1. 준비물

- Cloudflare 무료 계정 (https://dash.cloudflare.com/sign-up)
- Node.js (LTS 버전). 터미널에서 `node -v` 를 실행해 버전이 출력되면 설치된 것입니다.

용어는 다음처럼 씁니다.

| 용어 | 뜻 |
|---|---|
| 공간 | 동기화 키 하나에 대응하는 서버 쪽 데이터 묶음 |
| 동기화 키 | 앱이 만드는 26자 키. 같은 키를 입력한 기기끼리 한 공간을 공유함 |
| 초대 코드 | 새 공간을 만들 때만 요구하는 비밀 문자열. 직접 정함 |
| Worker 주소 | 배포 후 얻는 `https://….workers.dev` 주소 |

## 2. 배포 순서

모든 명령은 이 `sync-worker` 폴더에서 실행합니다. 터미널을 열고 이 폴더로 이동하세요.

### 2-1. 패키지 설치

```
npm install
```

확인: 오류 없이 끝나고 `node_modules` 폴더가 생깁니다.

### 2-2. Cloudflare 로그인

```
npx wrangler login
```

브라우저가 열리면 Cloudflare 계정으로 로그인하고 권한 요청을 허용합니다.
확인: `npx wrangler whoami` 에 본인 계정 이메일이 표시됩니다.

### 2-3. 데이터베이스 만들기

`wrangler.toml` 의 데이터베이스 이름은 `md-works-sync` 입니다. 같은 이름으로 만듭니다.

```
npx wrangler d1 create md-works-sync
```

출력에 `database_id` 가 나옵니다 (`xxxxxxxx-xxxx-…` 형태의 값).

1. `wrangler.toml` 을 텍스트 편집기로 엽니다.
2. `database_id = "<wrangler d1 create 출력값>"` 줄의 따옴표 안을 출력된 값으로 바꿉니다.

```toml
database_id = "여기에 출력된 값"
```

`wrangler.toml` 에는 데이터베이스 설정(`[[d1_databases]]`)이 이미 들어 있습니다.
명령이 "설정 파일에 바인딩을 추가할까요?"라고 물으면 `n`(아니오)을 고르고, 위 방법으로 값만 직접 바꿉니다.
질문 문구와 동작은 Wrangler 버전에 따라 다를 수 있으니, 화면이 다르면 공식 문서 https://developers.cloudflare.com/d1/get-started/ 를 확인하세요.

확인: `wrangler.toml` 에 `<` 나 `>` 문자가 남아 있지 않습니다.

### 2-4. 로컬에서 시험하기 (선택)

내 컴퓨터에서 먼저 동작을 확인하는 단계입니다. 건너뛰어도 됩니다.

```
npx wrangler d1 execute md-works-sync --local --file=./schema.sql
npx wrangler dev
```

`wrangler dev` 가 실행되는 동안 터미널에 `http://localhost:8787` 같은 주소가 표시됩니다.
확인: 다른 터미널이나 브라우저에서 그 주소 뒤에 `/v1/health` 를 붙여 열면 `{"ok":true}` 가 보입니다.
끝내려면 `wrangler dev` 터미널에서 `Ctrl+C` 를 누릅니다.

### 2-5. 원격 데이터베이스에 스키마 적용

```
npx wrangler d1 execute md-works-sync --remote --file=./schema.sql
```

실제 Cloudflare 데이터베이스를 변경한다는 확인 질문이 나오면 `y` 를 입력합니다.
확인: `spaces`, `items` 두 테이블을 만들었다는 실행 결과가 표시됩니다. 같은 명령을 다시 실행해도 안전합니다.

### 2-6. 배포

```
npx wrangler deploy
```

- 처음 배포할 때 `workers.dev` 하위 도메인을 등록하라는 질문이 나올 수 있습니다. 원하는 이름을 입력합니다. 이 이름이 Worker 주소에 들어갑니다.
- 배포가 끝나면 `https://md-works-sync.<하위도메인>.workers.dev` 형태의 Worker 주소가 출력됩니다. 이 주소를 적어 둡니다.
- 처음 배포 직후 주소에 접속하면 523 오류가 나올 수 있습니다. 1분쯤 기다린 뒤 다시 시도합니다.

### 2-7. 초대 코드 설정

```
npx wrangler secret put INVITE_CODE
```

입력 프롬프트가 나오면 원하는 초대 코드를 입력하고 Enter 를 누릅니다. 입력한 글자는 화면에 보이지 않을 수 있습니다.
추측하기 어려운 긴 문자열을 쓰고, 앱 연결 때 다시 입력해야 하므로 따로 적어 둡니다.
확인: `Success` 로 시작하는 메시지가 출력됩니다.

초대 코드를 설정하지 않으면 새 공간을 만들 수 없습니다(403).

### 2-8. 동작 확인

브라우저 주소창에 다음을 입력합니다.

```
https://md-works-sync.<하위도메인>.workers.dev/v1/health
```

확인: 화면에 `{"ok":true}` 가 보입니다.

## 3. 앱에 연결하기

1. md-works 스탠드얼론 HTML 을 열고 동기화 대화상자를 엽니다.
2. `Worker 주소` 칸에 2-6 에서 얻은 주소를 입력합니다. 주소는 `https://` 로 시작해야 합니다.
3. 연결 방법에서 `이 기기에서 새로 시작` 을 고릅니다.
4. `초대 코드` 칸에 2-7 에서 정한 코드를 입력하고 `새로 시작` 을 누릅니다.
5. 앱이 새 동기화 키를 보여 줍니다. 이 키를 안전한 곳에 적어 둡니다.

**동기화 키를 잃어버리면 복구할 수 없습니다.** 서버는 키를 알지 못하고, 키 없이는 데이터를 풀 수 없습니다.
키를 아는 사람은 누구나 이 데이터를 읽고 쓸 수 있으므로 남에게 보이지 않게 보관합니다.

다른 기기에서 연결하는 방법은 다음과 같습니다.

1. 동기화 대화상자에서 `Worker 주소` 를 입력합니다.
2. 연결 방법에서 `다른 기기의 키로 연결` 을 고릅니다.
3. `동기화 키` 칸에 키를 붙여 넣고 `연결` 을 누릅니다. 공백과 소문자는 자동으로 정리됩니다.

이 경우 초대 코드는 필요하지 않습니다.

이미지는 동기화되지 않습니다. 글·글감·코멘트만 동기화합니다. 다른 기기에서 이미지를 보려면 앱의 백업 번들로 옮깁니다.

## 4. 한도와 값 변경

### 4-1. 한도 값

한도는 `wrangler.toml` 의 `[vars]` 에 있습니다.

| 변수 | 기본값 | 의미 |
|---|---|---|
| `ALLOWED_APPS` | `md-works` | 새 공간을 만들 수 있는 앱 목록(쉼표로 구분) |
| `MAX_ITEM_BYTES` | `262144` | 글 하나(암호화된 상태)의 최대 크기. 약 256 KB |
| `MAX_SPACE_BYTES` | `5242880` | 공간 하나의 전체 저장 용량. 5 MB |
| `MAX_SPACES` | `60` | 서버에 만들 수 있는 공간 수 |
| `MAX_ITEMS_PER_SPACE` | `1000` | 공간 하나의 항목(글·글감·코멘트) 수 |
| `MAX_DAILY_WRITES` | `300` | 공간 하나의 하루 쓰기 횟수 (UTC 기준) |
| `TOMBSTONE_DAYS` | `30` | 삭제 기록을 보관하는 일수 |

앱은 같은 기본값을 기준으로 한도를 표시합니다. 서버 값을 바꿔도 앱의 표시 값은 바뀌지 않으므로, 기본값에서 크게 바꾸지 않는 편이 좋습니다.

### 4-2. 값을 바꾸는 방법

1. `wrangler.toml` 의 `[vars]` 에서 값을 수정합니다. 값은 따옴표로 감싼 문자열로 둡니다.
2. 다시 배포합니다.

```
npx wrangler deploy
```

`schema.sql` 을 수정했다면 2-5 의 원격 스키마 적용 명령을 다시 실행합니다.

### 4-3. Cloudflare 무료 플랜 한도

아래 값은 작성 시점에 알려진 값입니다. 최신 값은 공식 문서(https://developers.cloudflare.com/workers/platform/limits/, https://developers.cloudflare.com/d1/platform/limits/)를 확인하세요.

| 항목 | 무료 플랜 한도 |
|---|---|
| Workers 요청 | 하루 10만 회 |
| D1 쓰기 | 하루 10만 행 |
| D1 읽기 | 하루 500만 행 |
| D1 데이터베이스 크기 | 500 MB |

한도를 넘으면 다음 00:00 UTC (한국 시간 오전 9시)까지 요청이 실패합니다. 무료 플랜에서는 한도를 넘어도 요금이 청구되지 않습니다.
이 Worker 의 기본 한도(공간 60개 × 5 MB)는 데이터베이스 500 MB 안에 들어오도록 정했습니다.

## 5. 며칠 쓴 뒤 사용량 확인

1. Cloudflare 대시보드(https://dash.cloudflare.com)에 로그인합니다.
2. Workers & Pages 에서 `md-works-sync` 를 열고 요청 수를 확인합니다.
3. 대시보드의 D1 메뉴에서 `md-works-sync` 데이터베이스를 열고 쓰기 행 수와 저장 용량을 확인합니다.

메뉴 이름과 위치는 바뀔 수 있습니다. 찾을 수 없으면 공식 문서 https://developers.cloudflare.com/d1/ 를 확인하세요.

한도 조정 기준은 다음과 같습니다.

- 하루 요청 수나 쓰기 행 수가 무료 한도의 절반을 넘으면 `MAX_DAILY_WRITES` 를 낮춥니다.
- 저장 용량이 300 MB 에 가까워지면 `MAX_SPACES` 나 `MAX_SPACE_BYTES` 를 낮춥니다.
- 앱의 사용량 표시에서 `오늘 쓰기` 가 자주 한도에 닿으면 `MAX_DAILY_WRITES` 를 올립니다. 올린 만큼 D1 쓰기 행 수도 늘어납니다.

## 6. 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 401 `unauthorized` | 동기화 키가 이 공간의 키와 다르거나 앱 식별자가 맞지 않음 | 앱의 `키 다시 입력` 으로 올바른 키를 입력 |
| 403 `forbidden` | 초대 코드가 틀림, `INVITE_CODE` 미설정, `ALLOWED_APPS` 에 앱이 없음, 공간 수가 `MAX_SPACES` 에 도달 | 초대 코드를 확인하고 2-7 을 다시 실행. 값은 `wrangler.toml` 에서 확인 |
| 413 `body_too_large` | 한 번에 보내는 데이터가 너무 큼 | 앱이 나눠 보내므로 보통 재시도로 해결됨. 계속되면 큰 글을 줄임 |
| 422 `item_too_large` | 글 하나가 `MAX_ITEM_BYTES` 를 넘음 | 글을 나누거나 줄임. 줄이면 자동으로 올라감 |
| 422 `item_limit` | 항목 수가 `MAX_ITEMS_PER_SPACE` 를 넘음 | 쓰지 않는 글을 지우거나 값을 올리고 `npx wrangler deploy` |
| 422 `space_full` | 공간 용량이 `MAX_SPACE_BYTES` 를 넘음 | 쓰지 않는 글을 지우거나 값을 올리고 `npx wrangler deploy` |
| 429 `daily_write_limit` | 공간의 하루 쓰기가 `MAX_DAILY_WRITES` 에 도달 | 다음 00:00 UTC 이후 자동으로 이어짐. 글은 이 기기에 남음 |
| 503 `unavailable` | 서버나 데이터베이스가 일시적으로 응답하지 않음. 스키마 미적용일 때도 발생 | 잠시 후 자동 재시도. 계속되면 2-5 를 실행했는지 확인 |
| 523 | 처음 배포 직후 주소가 아직 준비되지 않음 | 1분 뒤 다시 시도 |
| 브라우저의 CORS 오류 | Worker 주소가 틀렸거나 Worker 가 오류로 응답하지 못함 | 주소 끝의 오타를 확인하고 `/v1/health` 가 열리는지 확인 |
| `file://` 로 연 HTML 에서 동작이 이상함 | 브라우저마다 `file://` 페이지의 요청과 저장 방식이 다름 | Worker 는 모든 출처의 요청을 허용하도록 만들었지만 `file://` 에서의 동작은 확인하지 못함. 문제가 있으면 HTTPS 로 연 페이지에서 시도 |
| 동기화 키를 잃음 | 서버가 키를 모름 | 복구할 수 없음. 이미 연결된 기기가 있으면 그 기기의 동기화 대화상자에서 키를 복사. 모든 기기에서 잃었다면 새 키로 `새로 시작` 해야 하며, 이전 공간의 데이터는 읽을 수 없음 |
| 초대 코드를 바꿈 | 이미 만들어진 공간은 초대 코드와 무관 | 기존 공간은 계속 동작함. 새 공간을 만들 때만 새 코드를 입력 |

## 7. 보안 메모

- 서버는 암호문만 가집니다. 글 내용과 글 이름은 이 기기에서 암호화한 뒤 올립니다.
- 동기화 키가 곧 접근 권한입니다. 키를 아는 사람은 데이터를 읽고 쓸 수 있습니다.
- 초대 코드는 새 공간 생성만 막습니다. 이미 만들어진 공간의 접근은 막지 않습니다.
- Worker 는 키와 토큰을 로그에 남기지 않습니다. 설정을 바꿀 때도 로그를 추가하지 마세요.
- 이 암호 설계는 외부 검증을 거치지 않았습니다.

## 8. 지원 범위

이 문서는 명령줄(CLI) 방식만 안내합니다. Cloudflare 대시보드만으로 설정하는 방법은 지원하지 않습니다.
