# Nushell 5단원 완벽 가이드: 변수와 표현식

Oct 29, 2026 · @KWON BONG SOO

## 이 단원에서 얻는 것

핵심은 세 문장이다. 값은 기본적으로 바뀌지 않는 변수(`let`)에 담고, 바뀌어야 할 때만 `mut`를 쓰며, 파싱 단계에서 값이 확정되어야 하는 곳에만 `const`를 쓴다. 연산자는 타입에 엄격해서 문자열과 정수를 섞으면 조용히 변환하지 않고 오류를 낸다. 구조화된 값 안으로 들어갈 때는 `.` 경로로 접근하고, 없을 수도 있는 값은 `?`를 붙여 안전하게 꺼낸다.

이 단원은 1\~4단원에서 한 줄 파이프라인으로 데이터를 다루던 독자가 스크립트다운 코드를 쓰기 시작하는 지점을 다룬다. 터미널 사용과 `ls`, `where`, `select` 같은 기본 명령은 알고, 프로그래밍 경험은 없어도 된다고 가정한다.

읽고 나면 다음을 할 수 있다.

- `let`, `mut`, `const` 중 상황에 맞는 선언을 고르고, 오류 메시지가 나왔을 때 이유를 설명한다.
- 산술, 비교, 논리, 포함, 정규식 연산자를 우선순위까지 고려해 조합한다.
- 문자열 보간 `$"..."`로 값과 문장을 섞어 출력하고, 괄호와 역슬래시 이스케이프 규칙을 틀리지 않는다.
- 범위 `1..5`와 `1..<5`의 차이를 알고 반복과 포함 검사에 쓴다.
- 리스트, 레코드, 테이블 안의 값을 `$list.0`, `$rec.name`, `$rec.missing?`로 꺼낸다.

먼저 이 단원 전체가 6줄로 압축된 맛보기를 본다. 각 줄의 이유는 뒤에서 하나씩 푼다.

```nu
let name = "kim"
mut score = 80
$score += 5
let passed = $score >= 60
print $"($name): ($score)점, 합격 ($passed)"
# => kim: 85점, 합격 true
```

**읽는 법.** 예제의 `# =>` 주석은 예상 출력이다. 기준 버전은 목차와 같은 Nushell 0.116.x 계열이다. 문법은 공식 책의 변수, 연산자, 문자열, 데이터 타입, 구조화 데이터 접근 페이지를 기준으로 작성했다. 다만 작성 환경에 `nu`가 없어 예제를 직접 실행해 보지는 못했으므로, 각자 `version`으로 버전을 확인한 뒤 예제를 실행해 출력을 대조하길 권한다. 출력 모양(표의 테두리, 소수점 자릿수)은 버전과 설정에 따라 조금 다를 수 있다.

## 5.1 let: 값에 이름을 붙이는 불변 변수

변수는 값에 붙이는 이름표다. 파이프라인에서는 값이 한 번 흘러가면 사라지므로, 같은 결과를 두 번 쓰거나 중간 결과에 의미 있는 이름을 붙이고 싶을 때 변수가 필요하다. Nushell에서 가장 기본이 되는 선언은 `let`이다.

```nu
let city = "Seoul"
$city
# => Seoul
```

문법은 `let 이름 = 식`이고, 값을 꺼낼 때는 `$이름`을 쓴다. `=` 양옆에는 공백을 둔다. `let` 자체는 값을 출력하지 않으므로 선언한 줄 아래에는 아무것도 나오지 않는다. 오른쪽에는 리터럴, 연산, 서브표현식, 파이프라인이 모두 올 수 있다.

```nu
let total = 3 + 4 * 2          # 연산식
let file_count = (ls | length) # 괄호로 감싼 파이프라인
let names = (ls | get name)    # 열 하나를 리스트로
```

괄호 `( )`는 안의 파이프라인을 실행해 결과를 하나의 값으로 만든다. 이를 서브표현식이라 하며 5.6절과 5.8절에서 다시 쓴다. 변수는 값의 타입을 그대로 보존하므로 `describe`로 확인할 수 있다.

```nu
let n = 42
let pi = 3.14
let ok = true
let langs = [nu bash zsh]
let me = {name: "kim", age: 30}

$n | describe      # => int
$langs | describe  # => list<string>
$me | describe     # => record<name: string, age: int>
```

### 기본이 불변인 이유

`let`으로 만든 변수는 선언 뒤에 값을 바꿀 수 없다. 바꾸려 하면 오류가 난다.

```nu
let val = 42
$val = 100
# => Error: nu::parser::assignment_requires_mutable_variable
# =>   x Assignment to an immutable variable.
```

공식 책은 이 설계의 배경을 이렇게 설명한다. Nushell은 처음 몇 년간 가변 변수가 없는 언어였고, 불변성과 파이프라인 조합에 크게 기댄 덕분에 `each`를 `par-each`로 바꾸기만 해도 같은 코드를 병렬로 돌릴 수 있었다. 즉 불변은 제약이 아니라 병렬화와 스트리밍을 가능하게 하는 기반이다. 오류의 도움말은 해결책으로 `mut`를 선언하거나 `let`으로 다시 선언(섀도잉)하라고 안내한다.

### 섀도잉: 값을 바꾸는 것이 아니라 이름표를 옮기는 것

같은 스코프에서 같은 이름을 `let`으로 다시 선언하면 이전 변수는 가려진다. 이를 섀도잉이라 한다.

```nu
let val = 42
let val = $val + 1   # 오른쪽의 $val은 이전 변수(42)
$val
# => 43
```

여기서 `$val`은 이전 변수를 읽어 새 변수를 만든 것이지 42를 43으로 고친 것이 아니다. 안쪽 스코프에서의 섀도잉은 바깥에 영향을 주지 않는다.

```nu
let val = 42
do { let val = 101; $val }
# => 101
$val
# => 42
```

`do { ... }`는 코드 블록을 한 번 실행하는 명령이다. 블록 안에서 만든 `val`은 블록이 끝나면 사라지고 바깥의 `val`은 그대로다. 이 성질은 `if`, `for` 같은 블록에서도 같다.

```nu
if true { let inner = 1 }
$inner
# => Error: Variable not found.
```

**오해 교정.** 섀도잉은 변수를 수정하는 것이 아니다. 이미 만들어진 클로저는 만들어질 당시의 변수를 계속 가리킨다.

```nu
let n = 1
let show = { $n }
let n = 2
do $show
# => 1
```

### 파이프라인 안에서 let 쓰기와 unlet

`let`은 파이프라인의 중간이나 끝에도 놓을 수 있다. 끝에 두면 입력을 변수에 저장하고 그 값을 출력하며, 출력이 싫으면 `| ignore`를 붙인다. 중간에 두면 저장한 뒤 값을 그대로 다음 명령으로 넘긴다.

```nu
ls | length | let file_count | ignore   # 저장만 하고 출력 없음
ls | let files | length                   # files에 저장하면서 length로 계속 진행
```

더 이상 필요 없는 변수는 `unlet`으로 지울 수 있고, 이후에 쓰면 `Variable not found` 오류가 난다. 큰 데이터를 담은 변수를 일찍 놓아 줄 때 쓴다.

```nu
let temp = 1
unlet $temp
```

### REPL과 스크립트의 차이

대화형 셸에서는 `$val`만 쳐도 값이 출력된다. 스크립트 파일에서는 마지막 식의 값만 출력되므로 중간 값을 보려면 `print $val`을 쓴다. 10단원에서 스크립트를 다룰 때 다시 만난다.

**판단 기준.** 새 값이 필요하면 먼저 `let`으로 새 이름을 짓는다. 같은 이름을 다시 선언하는 섀도잉은 `let path = $path | path expand`처럼 같은 개념의 정제된 값일 때만 쓴다.

## 5.2 mut: 값이 바뀌어야 할 때

카운터, 합계, 누적 목록처럼 반복하면서 값이 계속 바뀌는 경우에는 `mut`로 선언한다. `let`과 선언 문법은 같고, 이후 할당 연산자로 값을 바꿀 수 있다.

```nu
mut count = 0
$count += 1
$count += 1
$count
# => 2
```

할당에서는 `$count = ...`처럼 변수 앞에 `$`를 붙인다. 선언할 때(`mut count`)와 달리 이미 있는 변수를 가리키기 때문이다. 쓸 수 있는 할당 연산자는 다음과 같다.

| 연산자 | 의미 | 예 |
| --- | --- | --- |
| `=` | 새 값을 대입 | `$x = 10` |
| `+=` | 더해서 저장 | `$x += 5` |
| `-=` | 빼서 저장 | `$x -= 5` |
| `*=` | 곱해서 저장 | `$x *= 2` |
| `/=` | 나눠서 저장 | `$x /= 2` |
| `++=` | 리스트, 문자열, 바이너리를 이어 붙여 저장 | `$names ++= ["lee"]` |

복합 연산자는 그 뒤에 숨은 기본 연산이 성립하는 곳에서만 쓸 수 있다. 특히 `/`는 항상 float을 돌려주므로 정수 변수에 `$x /= 2`를 쓰면 타입이 맞지 않아 실패한다. 정수를 유지하려면 `$x = $x // 2`처럼 정수 나눗셈 `//`를 쓴다. `++=`는 양쪽의 종류가 같아야 하므로 리스트에 항목 하나를 붙일 때는 `$list ++= [$item]`처럼 리스트로 감싼다.

### 반복문 안에서는 변경할 수 있다

```nu
mut total = 0
for n in 1..5 {
  $total += $n
}
$total
# => 15
```

`for n in 1..5 { ... }`는 범위의 값을 하나씩 `n`에 담아 블록을 실행한다. `for`, `while`, `loop`, `if`, `match`가 받는 `{ ... }`는 블록이고, 블록은 바깥의 `mut` 변수를 직접 바꿀 수 있다. `if` 안에서 `$x += 1000`을 해도 바깥의 `$x`가 바뀐다.

### 클로저 안에서는 변경할 수 없다

```nu
mut count = 0
[1 2 3] | each { $count += 1 }
# => Error: Capture of mutable variable.
```

`each`, `where`, `reduce`, `do`가 받는 `{ ... }`는 클로저다. 클로저는 값을 캡처해서 나중에 실행되거나 병렬로 실행될 수 있기 때문에, 공유되는 가변 상태를 허용하지 않는다. 중첩된 `def`도 바깥의 `mut` 변수를 캡처하지 못한다. 에러가 나면 코드가 틀린 것이 아니라 도구를 잘못 고른 것이다. 선택지는 둘이다. 반복문(`for`, `while`)으로 바꾸거나, 아예 누적 자체를 함수형으로 표현한다.

```nu
[1 2 3] | length                             # => 3
1..5 | math sum                              # => 15
[1 2 3 4] | reduce {|it, acc| $acc + $it}    # => 10
```

`reduce`는 항목을 하나씩 받아 누적값(`acc`)을 갱신하는 명령이며 6단원에서 자세히 다룬다. 공식 책은 가변 변수 사용처의 상당수가 불변 변수만 쓰는 함수형 해법으로 대체되고, 그쪽이 대체로 더 빠르며 스트리밍을 지원한다고 설명한다. 실제로 책에는 `for`와 `mut`로 리스트를 만드는 방식과 `each`로 만드는 방식을 `timeit`으로 비교하는 예가 있으므로, 큰 데이터에서는 12단원에서 직접 측정해 보자.

### 레코드와 리스트 값을 바꾸는 법

레코드의 필드를 바꾸는 명령 `update`, `merge`, `insert`는 원본을 고치지 않고 새 레코드를 돌려준다. 그러므로 `mut` 변수에 다시 대입한다. 공식 책이 이 명령들을 소개한다.

```nu
mut user = {name: "kim", age: 30}
$user = ($user | update age { $in + 1 })    # 기존 필드 값 교체
$user = ($user | merge {city: "Seoul"})    # 필드 추가 또는 덮어쓰기
$user
# => name: kim, age: 31, city: Seoul

mut names = ["kim"]
$names ++= ["lee"]
$names
# => [kim, lee]
```

`update age { $in + 1 }`에서 `$in`은 그 필드의 현재 값이다. 필드가 없으면 `update`는 실패하므로 없을 수도 있는 필드에는 `upsert`를 쓴다. `$user.age = 31`처럼 필드에 직접 대입하는 문법도 쓰이지만, 이 가이드를 쓰며 연 공식 페이지에서는 확인하지 못했다. 직접 써 보고 오류가 나면 위의 `update` 방식을 쓰면 된다.

**판단 기준.** 기본은 `let`이다. 반복하면서 누적해야 하고 그 반복이 `for`나 `while` 블록이면 `mut`를 쓴다. `mut`를 `each` 같은 클로저 안에서 바꾸고 싶어졌다면 설계를 바꿀 신호이므로 `reduce`나 `math sum`, `length` 같은 명령으로 표현할 수 있는지 먼저 본다.

## 5.3 const, 변수 이름 규칙, 타입 어노테이션

### const: 실행 전에 확정되는 상수

`const`는 불변 변수 중에서도 파싱 시점에 값이 완전히 계산되는 변수다. Nushell은 코드를 실행하기 전에 먼저 전체를 파싱하는데, `source`, `use`, `plugin use`처럼 파일 경로를 파싱 단계에서 알아야 하는 명령은 실행 중에 정해지는 `let` 변수를 받을 수 없다. 그 자리에 쓰려고 만든 것이 `const`다.

```nu
const script_file = 'hello.nu'
source $script_file
```

`const`의 오른쪽에는 리터럴처럼 파싱 시점에 값이 정해지는 식만 올 수 있다. 공식 책에는 `const x = $"(2kb)"`처럼 보간을 쓰는 예도 있다. 실행해 봐야 알 수 있는 값(예: 파일 목록)을 넣으면 파싱 단계에서 오류가 난다. 같은 코드를 `let script_file = 'hello.nu'`로 바꾸면 `source $script_file`이 값을 알 수 없다고 거부하는 이유도 이것이다.

세 선언을 한 번에 비교하면 다음과 같다.

| 선언 | 값 변경 | 값이 정해지는 시점 | 주 용도 | 클로저에서 |
| --- | --- | --- | --- | --- |
| `let` | 불가 | 실행 시점 | 일반적인 값과 중간 결과 | 읽을 수 있음 |
| `mut` | 가능 | 실행 시점 | `for`, `while` 블록의 카운터와 누적값 | 캡처할 수 없음 |
| `const` | 불가 | 파싱 시점 | `source`, `use` 인자 등 | 읽을 수 있음 |

### 변수 이름 규칙

변수 이름에는 다음 문자를 쓸 수 없다.

```text
. [ ( { + - * ^ / = ! < > & |
```

이 문자들은 모두 Nushell 문법에서 다른 뜻을 가진다. 특히 `-`는 뺄셈이라서 `$a-b`가 변수 이름인지 연산인지 모호해진다. 그래서 명령 이름은 `sort-by`처럼 하이픈(kebab-case)을 쓰지만, 변수는 `file_count`처럼 밑줄(snake\_case)을 쓴다.

```nu
let file_count = 3      # 올바름
let file-count = 3      # 오류: 이름에 - 사용 불가
```

`let $var = 42`처럼 이름 앞에 `$`를 붙여도 되고, 이것은 `let var = 42`와 같다. 다른 언어의 습관이 남은 스크립트에서 흔히 보이지만 새로 쓸 때는 `$` 없이 쓰는 편이 일관적이다.

### 타입 어노테이션: 변수에 타입을 못 박기

변수 이름 뒤에 `: 타입`을 붙이면 그 타입의 값만 받겠다고 선언한 것이다.

```nu
let age: int = 30
let name: string = "kim"
let ids: list<int> = [1 2 3]
mut total: float = 0.0
```

값의 타입이 어긋나면 파싱 단계에서 타입이 맞지 않는다는 오류가 난다.

```nu
let age: int = "thirty"
# => Error: 타입 불일치 (int가 필요한 곳에 string)
```

어노테이션은 필수가 아니다. 타입은 값에서 추론되므로 짧은 스크립트에서는 생략해도 된다. 대신 값이 어디서 왔는지 한눈에 알기 어려운 곳(함수 인자, 파일에서 읽은 값)에서는 어노테이션이 일종의 안전장치가 된다. 외부 데이터는 문자열로 들어오는 경우가 많아서 먼저 변환해야 한다.

```nu
let n: int = ("42" | into int)
$n | describe
# => int
```

`record<name: string, age: int>`처럼 세부 구조까지 지정하는 방법은 8단원과 11단원에서 다룬다.

**판단 기준.** `source`나 `use`에 넘길 경로가 아니라면 `const`는 거의 필요 없다. 이름은 snake\_case로 짓고, 타입을 확신할 수 없는 곳에는 어노테이션이나 `into`로 먼저 변환해 둔다.

## 5.4 산술, 비교, 논리 연산자와 우선순위

연산자는 값과 값을 이어 새 값을 만드는 기호다. Nushell 연산자의 가장 큰 특징은 타입에 엄격하다는 점이다. 이 엄격함 덕분에 실수가 조용히 넘어가지 않고 곧바로 드러난다. 연산자 양옆에는 공백을 두어야 한다. 공백이 없으면 `1+2`가 연산이 아니라 하나의 단어로 읽힐 수 있다.

### 산술 연산자

```nu
7 + 3      # => 10
7 - 3      # => 4
7 * 3      # => 21
7 / 2      # => 3.5
10 / 2     # => 5.0
7 // 2     # => 3
7 mod 3    # => 1
2 ** 10    # => 1024
```

- `/`는 항상 float을 돌려준다. `10 / 2`도 `5`가 아니라 `5.0`이다.
- `//`는 정수 나눗셈(내림)이고, `mod`는 나머지, `**`는 거듭제곱이다.
- 앞 절에서 `$x /= 2`가 정수 변수에서 실패한 이유가 바로 이것이다. 정수를 유지하려면 `//`를 쓴다.

파일 크기와 기간도 값이라서 같은 연산자로 계산한다. 공식 책의 예제를 그대로 가져오면 다음과 같다.

```nu
0.5kB
# => 500 B
1GiB / 1B
# => 1073741824.0
(1GiB / 1B) == 2 ** 30
# => true
3.14day
# => 3day 3hr 21min 36sec
30day / 1sec
# => 2592000.0
```

단위가 있는 값끼리 나누면 단위가 사라지고 숫자(float)가 된다. 그래서 `1GiB / 1B`는 바이트 수가 된다.

### 비교 연산자

`==`, `!=`, `<`, `<=`, `>`, `>=`는 `bool`을 돌려준다. 문자열은 대소문자를 구분해 사전순으로, 날짜는 시간순으로 비교한다.

```nu
5 > 3                         # => true
"apple" < "banana"            # => true
"Apple" == "apple"            # => false
2026-01-01 < 2026-06-01       # => true
```

`ls | where size > 1mb`처럼 4단원에서 쓴 `where` 조건도 결국 비교 연산자다. `==`는 같은지를 묻는 비교이고 `=`는 대입이라는 점을 구분해야 한다. `if $x = 5`처럼 쓰면 대입이 되어 오류가 난다.

### 논리 연산자

`and`, `or`, `xor`, `not`은 bool에만 쓸 수 있다. `and`와 `or`는 단락 평가를 한다. 왼쪽 값만으로 결과가 정해지면 오른쪽은 계산하지 않는다.

```nu
true and false    # => false
true or false     # => true
true xor true     # => false
not true          # => false

let age = 25
$age >= 20 and $age < 30    # => true
```

마지막 줄에 괄호가 없어도 동작하는 이유는 비교 연산자가 `and`보다 우선순위가 높아서다. 숫자나 문자열을 `and`에 넘기면 타입 오류가 난다. 다른 언어처럼 0이나 빈 문자열을 거짓으로 취급하지 않는다.

### 우선순위

여러 연산자가 한 식에 있을 때 계산 순서는 우선순위가 정한다. 높은 쪽부터 나열하면 다음과 같다.

| 순위 | 연산자 |
| --- | --- |
| 1 | 괄호 `( )` |
| 2 | `**` |
| 3 | `*`, `/`, `//`, `mod` |
| 4 | `+`, `-` |
| 5 | `bit-shl`, `bit-shr` |
| 6 | 비교, 포함(`in`), `starts-with`, `ends-with`, 정규식(`=~`), `++` |
| 7 | `bit-and` |
| 8 | `bit-xor` |
| 9 | `bit-or` |
| 10 | `not` |
| 11 | `and` |
| 12 | `xor` |
| 13 | `or` |
| 14 | 할당 (`=`, `+=` 등) |

셸에서 `help operators | sort-by precedence -r`를 실행하면 현재 버전의 순서를 직접 볼 수 있다.

```nu
2 + 3 * 4 ** 2        # => 50   (4 ** 2 = 16, 3 * 16 = 48, 2 + 48)
(2 + 3) * 4 ** 2      # => 80
3 * (1 + 2)           # => 9
false and false or true   # => true  (and가 or보다 먼저)
```

`not`은 비교보다 낮은 순위이므로 `not $x > 3`은 `not ($x > 3)`으로 읽힌다. 표를 외우려 하기보다는, 의도가 조금이라도 헷갈리는 식에는 괄호를 쳐서 읽는 사람에게 순서를 알려 주는 편이 좋다.

### 엄격한 타입 규칙

```nu
"spam" - 1
# => Error: The '-' operator does not work on values of type 'string'.
```

문자열에 뺄셈은 의미가 없으므로 Nushell은 변환을 시도하지 않고 멈춘다. `"5" + 1`이 `51`이 되거나 `6`이 되는 모호함 대신 오류를 택한 것이다. 의도한 타입으로 먼저 바꿔 준다.

```nu
("5" | into int) + 1       # => 6
$"(5)점"                    # => 5점  (숫자를 문자열로: 보간)
(5 | into string) ++ "점"  # => 5점
```

문자열을 이어 붙일 때는 `++`를 쓴다. `++`는 리스트끼리, 문자열끼리, 바이너리끼리 이어 붙이며 종류가 다르면 오류다. 리스트에 항목 하나를 붙일 때는 항목을 리스트로 감싼다.

```nu
"foo" ++ "bar"       # => foobar
[1 2] ++ [3]         # => [1, 2, 3]
[1 2] ++ 3           # => Error: 리스트에는 리스트만 이어 붙일 수 있음
```

비트 연산자 `bit-and`, `bit-or`, `bit-xor`, `bit-shl`, `bit-shr`도 있지만 셸 스크립트에서는 드물게 쓰므로 이 가이드에서는 이름만 소개한다.

**판단 기준.** 계산 결과가 정수여야 하면 `//`, 소수여야 하면 `/`를 쓴다. 타입이 다른 값을 섞을 때는 `into int`, `into string`, 문자열 보간으로 먼저 맞추고, 순서가 한눈에 안 읽히는 식은 괄호로 감싼다.

## 5.5 포함과 패턴 연산자: in, has, =\~, starts-with

"이 값이 저기 들어 있는가", "이 문자열이 이 패턴과 맞는가"를 묻는 연산자들이다. `where`의 조건식에서 가장 자주 쓰이고, 결과는 모두 bool이다.

### in, not-in, has, not-has

`in`은 왼쪽 값이 오른쪽 안에 들어 있는지, `has`는 왼쪽이 오른쪽을 가지고 있는지를 묻는다. 둘은 방향만 반대이고 같은 질문이다. 오른쪽에 올 수 있는 것은 리스트, 문자열, 레코드이며, 레코드일 때는 키를 검사한다.

```nu
3 in [1 2 3]                 # => true
4 in [1 2 3]                 # => false
5 not-in [1 2 3]             # => true
"ell" in "hello"             # => true   (부분 문자열)
"name" in {name: "kim"}      # => true   (레코드의 키)

[1 2 3] has 2                # => true
"hello" has "ell"            # => true
{name: "kim"} has "name"     # => true
[1 2 3] not-has 9            # => true
```

읽는 법을 정해 두면 실수가 줄어든다. `A in B`는 "A가 B 안에 있다"이고 `B has A`는 "B가 A를 가졌다"이다. 값이 앞에 오는 문장은 `in`, 컨테이너가 앞에 오는 문장은 `has`로 쓰면 자연스럽다. `in`과 `has`는 정규식을 쓰지 않고 있는 그대로 비교한다.

### starts-with, ends-with

문자열의 앞이나 뒤가 맞는지 검사한다. 부정형으로 `not-starts-with`, `not-ends-with`도 있다.

```nu
"nushell" starts-with "nu"     # => true
"report.md" ends-with ".md"    # => true
"report.md" not-ends-with ".txt"  # => true
```

3단원에서 글롭으로 확장자를 골랐다면, 이미 가져온 테이블에서 이름을 거를 때는 이렇게 쓴다.

```nu
ls | where name ends-with ".md"
```

### =\~ 와 !\~: 정규식 일치

`문자열 =~ 패턴`은 문자열 안에 패턴과 맞는 부분이 있으면 true이다. `!~`는 그 반대이고, `like`와 `not-like`는 각각의 별칭이다. 내부적으로는 Rust regex 크레이트의 `is_match()`를 쓴다.

```nu
"nushell" =~ "^nu"        # => true   (^는 문자열의 시작)
"nushell" =~ "shell$"     # => true   ($는 문자열의 끝)
"nushell" =~ "bash"       # => false
"nushell" !~ "bash"       # => true
"abc123" =~ '\d+'         # => true   (\d는 숫자, +는 한 번 이상)
ls | where name =~ '\.md$'
```

패턴에는 백슬래시가 자주 나오므로 이스케이프를 해석하지 않는 작은따옴표 문자열을 권한다. 큰따옴표 안에서는 `\\d`처럼 백슬래시를 두 번 써야 한다.

**오해 교정.** `=~`는 "같다"가 아니라 "포함하는 패턴이 있다"는 뜻이다. `"nushell" =~ "nu"`는 true이다. 전체가 일치해야 하면 `^nu$`처럼 시작과 끝을 고정한다. 또 `.`, `+`, `*`, `(` 같은 문자는 정규식에서 특별한 뜻이므로, 정규식 지식 없이 단순히 "이 글자가 들어 있나"만 확인하려면 `in`이나 `has`가 안전하다. `"a.b" =~ "a.b"`는 `axb`에도 맞는다.

### 대소문자 구분

문자열 연산자는 기본적으로 대소문자를 구분한다. 구분하지 않으려면 세 가지 방법이 있다.

```nu
"FOO" =~ "foo"                                      # => false
"FOO" =~ "(?i)foo"                                  # => true   (정규식의 (?i) 수식어)
"FOO" | str contains --ignore-case "foo"            # => true
("FOO" | str downcase) == ("Foo" | str downcase)    # => true   (둘 다 소문자로)
```

### 어떤 연산자를 고를까

| 알고 싶은 것 | 쓸 연산자 | 이유 |
| --- | --- | --- |
| 값이 리스트에 있는가 | `in` | 정확한 값 비교 |
| 레코드에 키가 있는가 | `in` 또는 `has` | 키 검사 |
| 문자열이 어떤 글자를 포함하는가 | `in`, `has` | 정규식 특수문자 걱정 없음 |
| 앞이나 뒤가 맞는가 | `starts-with`, `ends-with` | 의도가 이름에 드러남 |
| 복잡한 규칙에 맞는가 | `=~` | 정규식이 필요할 때만 |

**판단 기준.** 정확한 값 확인은 `in`과 `has`, 앞뒤 확인은 `starts-with`와 `ends-with`, 규칙이 복잡할 때만 `=~`를 쓴다. 대소문자가 섞인 데이터라면 비교하기 전에 `str downcase`로 맞춘다.

## 5.6 문자열과 문자열 보간

스크립트에서 값을 사람이 읽을 문장으로 바꾸거나, 변수로 파일 이름과 메시지를 만드는 일은 거의 매번 생긴다. Nushell은 용도별로 여러 문자열 형식을 제공하고, 그중 변수를 끼워 넣는 형식이 문자열 보간이다.

### 문자열 형식 한눈에 보기

| 형식 | 예 | 이스케이프 | 비고 |
| --- | --- | --- | --- |
| 작은따옴표 | `'hello world'` | 없음 | 안에 작은따옴표를 넣을 수 없음 |
| 큰따옴표 | `"The\nEnd"` | C 스타일 백슬래시 | 문자 그대로의 백슬래시는 `\\`로 써야 함 |
| 원시(raw) 문자열 | `r#'It's raw'#` | 없음 | 작은따옴표를 포함할 수 있음 |
| 베어워드 | `ozymandias` | 없음 | 단어 문자만 가능, 명령 위치에서는 불가 |
| 작은따옴표 보간 | `$'Captain ($name)'` | 없음 | 안에 `'`나 짝 없는 괄호 불가 |
| 큰따옴표 보간 | `$"Captain ($name)"` | C 스타일 백슬래시 | 문자 그대로의 백슬래시와 괄호는 이스케이프 필요 |

이 밖에 역따옴표(backtick)로 감싼 문자열이 있다. 공백을 포함할 수 있는 베어워드로, 명령 위치에 두면 경로나 명령으로 해석된다. 이 단원에서는 쓰지 않는다. 고르는 요령은 간단하다. 기본은 작은따옴표이고, 줄바꿈이나 탭이 필요하면 큰따옴표, 작은따옴표를 포함해야 하면 큰따옴표나 원시 문자열이다.

```nu
'C:\Users\kim'            # 백슬래시가 그대로 들어간다
"C:\\Users\\kim"          # 큰따옴표에서는 백슬래시를 두 번
"line1\nline2"            # 줄바꿈 포함
"a\tb"                    # 탭 포함
"\u{AC00}"                # => 가   (유니코드 코드포인트)
r#'It's "raw"'#           # => It's "raw"
```

큰따옴표 문자열에서 쓸 수 있는 이스케이프는 `\"`, `\'`, `\\`, `\/`, `\b`, `\f`, `\r`, `\n`, `\t`, 그리고 16진수 1\~6자리로 문자를 지정하는 `\u{...}`이다. 윈도 경로처럼 백슬래시가 많은 문자열은 작은따옴표로 쓰면 편하다.

### 문자열 보간: 값을 문장에 끼워 넣기

문자열 앞에 `$`를 붙이고, 끼워 넣을 식을 괄호 `( )`로 감싼다. 괄호 안의 식은 실행되어 결과가 문자열에 들어간다.

```nu
let name = "Alice"
$"greetings, ($name)"
# => greetings, Alice

$"2 + 2 is (2 + 2) \(you guessed it!)"
# => 2 + 2 is 4 (you guessed it!)
```

두 번째 예제에서 `(2 + 2)`는 식이라서 4로 바뀌고, `\(`는 문자 그대로의 여는 괄호다. 괄호 안에는 변수뿐 아니라 연산, 필드 접근, 파이프라인도 쓸 수 있다.

```nu
let user = {name: "kim", age: 30}
$"($user.name)님은 ($user.age)세입니다."
# => kim님은 30세입니다.

$"내년에는 ($user.age + 1)세"
# => 내년에는 31세

$"이름: ($user.name | str upcase)"
# => 이름: KIM

$"현재 폴더에는 (ls | length)개의 항목이 있다"
# => 현재 폴더에는 N개의 항목이 있다
```

`$user.name | str upcase`는 이름을 대문자로 바꾸는 파이프라인이고, 괄호 안이므로 하나의 값으로 계산되어 문장에 들어간다. 숫자, bool, 날짜는 자동으로 문자열이 되므로 `into string`을 따로 붙이지 않아도 된다.

**주의: 괄호는 항상 식이다.** 문장에 괄호를 그대로 쓰려면 이스케이프해야 한다. 이 규칙은 `$"..."` 형식에서 괄호를 이스케이프할 수 있게 된 0.61 버전부터 있다.

```nu
$"합계 (5건)"      # 오류: 괄호 안 `5건`을 식으로 해석하려 함
$"합계 \(5건)"     # => 합계 (5건)
```

큰따옴표 보간에서는 백슬래시도 이스케이프의 시작이므로 문자 그대로의 백슬래시는 `\\`로 쓴다. 이스케이프를 해석하지 않는 작은따옴표 보간 `$'...'`은 백슬래시가 많은 경로에 유용하지만, 안에 작은따옴표를 쓸 수 없고 괄호는 항상 짝이 맞아야 한다.

**참고: 설정이 영향을 주는 값.** 보간은 파일 크기나 날짜 같은 값을 문자열로 바꿀 때 `config.nu`의 표시 설정을 따른다. 공식 책은 `const x = $"(2kb)"`가 설정과 무관하게 "2.0 KB"가 된다는 예를 든다. `config.nu`가 로드되기 전에는 기본 설정으로 포맷된다.

### 보간으로 경로를 만들 때

```nu
let dir = "notes"
let file = "today.md"
$"($dir)/($file)"             # => notes/today.md
[$dir $file] | path join       # => notes/today.md (윈도에서는 notes\today.md)
```

보간은 간단하지만 구분자(`/`)를 직접 적게 된다. 운영체제를 가리지 않아야 하는 경로는 3단원의 `path join`이 안전하다.

**판단 기준.** 값이 섞이는 문장은 `$"..."`, 값이 섞이지 않는 문자열은 작은따옴표, 줄바꿈과 탭이 필요하면 큰따옴표, 경로는 `path join`을 쓴다.

## 5.7 범위: 1..5 와 1..<5

"1부터 5까지"를 일일이 적는 대신 시작과 끝만 적는 값이 범위(range)다. 반복문, 숫자 생성, 포함 검사에서 자주 쓴다. 타입 이름은 `range`이다.

### 기본 문법

```nu
1..5          # => [1, 2, 3, 4, 5]    끝 값을 포함
1..<5         # => [1, 2, 3, 4]       끝 값을 제외
0..2..10      # => [0, 2, 4, 6, 8, 10]  가운데 값으로 간격(stride) 지정
5..1          # => [5, 4, 3, 2, 1]    내려가는 범위
..3           # => [0, 1, 2, 3]       시작을 생략하면 0
```

- `시작..끝`은 기본적으로 끝 값을 포함한다(포함 범위). 끝 값을 빼고 싶으면 `..<`를 쓴다.
- 세 값으로 쓰는 `시작..다음값..끝`은 시작과 다음 값의 차이가 간격이 된다. `0..2..10`은 간격 2다.
- 시작을 생략하면 0이다. `..5`와 `0..5`는 같다.
- 연산자 `..` 양옆에는 공백을 쓰지 않는다. 변수는 `1..$n`처럼 바로 붙이고, 식은 `1..($n + 1)`처럼 괄호로 감싼다.

### 끝이 없는 범위와 지연 평가

끝을 생략하면 끝이 없는 범위가 된다. 범위는 값이 필요해질 때까지 계산하지 않는 지연 평가(lazy) 값이라서, 일부만 꺼내 쓰는 것은 안전하다.

```nu
1.. | take 5      # => [1, 2, 3, 4, 5]
1.. | describe    # => range
```

`take 5`는 앞에서 5개만 꺼내는 명령이다. 공식 책도 끝없는 범위를 이렇게 일부만 소비하는 예를 든다.

끝없는 범위를 그대로 출력하면 멈추지 않으므로 `Ctrl+C`로 중단해야 한다. 이 성질 덕분에 큰 범위(`1..1_000_000`)를 만들어도 값을 모두 메모리에 올려 두지 않는다.

### 범위를 쓰는 곳

```nu
1..5 | each {|n| $n * $n}             # => [1, 4, 9, 16, 25]
1..10 | where {|n| $n mod 2 == 0}      # => [2, 4, 6, 8, 10]
1..100 | math sum                      # => 5050

for i in 1..3 { print $i }             # 1, 2, 3을 한 줄씩 출력

[a b c d e] | slice 1..3               # => [b, c, d]   (인덱스 1부터 3까지)
```

- `each {|n| ... }`는 항목마다 클로저를 실행해 결과 리스트를 만든다. `|n|`은 항목을 받는 이름이다. 6단원에서 자세히 다룬다.
- `where {|n| ... }`는 조건이 true인 항목만 남긴다.
- `math sum`은 합계를 구한다.
- `for i in 1..3 { ... }`는 범위의 값을 하나씩 `i`에 담아 블록을 실행한다.
- `slice`는 리스트의 일부를 범위로 잘라 내며, 범위의 끝 값이 포함된다.

리스트 길이만큼 인덱스를 돌 때는 끝 값을 제외하는 `..<`가 알맞다. 인덱스는 0부터 시작하고 길이가 3이면 마지막 인덱스는 2이기 때문이다.

```nu
let items = [a b c]
for i in 0..<($items | length) {
  print $"($i): ($items | get $i)"
}
# => 0: a
# => 1: b
# => 2: c
```

`get $i`는 인덱스 `i`의 항목을 꺼내는 명령이다. 이렇게 인덱스를 직접 다루는 대신 `enumerate`로 인덱스와 값을 함께 받는 방법도 있으며 6단원에서 만난다.

### 범위를 변수에 담고 형태를 확인하기

```nu
let r = 1..5
$r | describe        # => range
$r | math sum        # => 15
```

문자나 날짜의 연속은 범위 문법 대신 `seq char`, `seq date` 명령이 있다. 예를 들어 `seq char a e`는 `a`부터 `e`까지의 문자를 만든다.

**오해 교정.** `1..5`는 숫자 5개이지만 `1..<5`는 4개다. 반복 횟수를 세는 용도라면 `0..<5`는 0,1,2,3,4로 정확히 5개라서 끝 값 제외 범위가 편하다. 반대로 "1부터 N까지"처럼 사람이 말하는 범위는 포함 범위가 자연스럽다.

**판단 기준.** 끝 값을 포함하고 싶으면 `..`, 개수나 인덱스를 다루면 `..<`를 쓴다. 범위 끝이 계산된 값이면 괄호로 감싼다.

## 5.8 리스트와 레코드 접근: 셀 경로와 ? 접근

변수에 담긴 구조화된 값 안에서 원하는 조각을 꺼내는 문법이 셀 경로(cell path)다. 점(`.`)으로 이름과 인덱스를 이어 가는 단순한 규칙 하나로 레코드, 리스트, 테이블, 중첩 구조까지 모두 접근한다.

### 레코드, 리스트, 테이블

```nu
let rec = {a: 5, b: 42}
$rec.b + 5                  # => 47

let crew = [Velma Fred Daphne Shaggy Scooby]
$crew.2                     # => Daphne   (인덱스는 0부터)

let t = [[name age]; [kim 30] [lee 25]]
$t.name                     # => [kim, lee]       열 하나가 리스트로
$t.0                        # => {name: kim, age: 30}   행 하나가 레코드로
$t.1.name                   # => lee              행 다음에 열: 셀 하나
```

레코드는 키 이름, 리스트는 0부터 시작하는 정수 인덱스로 접근한다. 테이블은 "레코드의 리스트"이므로 두 규칙이 겹친다. 열 이름을 쓰면 그 열 전체가 리스트로, 행 번호를 쓰면 그 행이 레코드로 나오고, 둘을 이으면 셀 하나가 나온다. `[[name age]; [kim 30] [lee 25]]`는 첫 대괄호가 열 이름이고 세미콜론 뒤가 행인 테이블 리터럴이다. 다른 언어의 `$crew[2]`와 같은 대괄호 접근은 쓰지 않는다.

중첩된 값은 경로를 계속 이으면 된다.

```nu
let cfg = {server: {host: "localhost", port: 8080}, tags: [web api]}
$cfg.server.port            # => 8080
$cfg.tags.1                 # => api
$"($cfg.server.host):($cfg.server.port)"   # => localhost:8080
```

파이프라인 결과에도 같은 경로를 쓸 수 있다. 서브표현식으로 감싸 변수처럼 다루거나 `get` 명령을 쓴다. 두 줄은 같은 결과다.

```nu
(ls).name
ls | get name
```

### 키에 공백이 있거나 숫자처럼 보일 때

경로의 각 부분은 베어워드이므로 공백이 있는 키나 숫자처럼 보이는 키는 따옴표로 감싼다. 숫자 `1`은 행 번호이고 문자열 `"1"`은 키 이름으로 구분된다.

```nu
let r = {"key x": 12, "1": foo}
$r."key x"                  # => 12
$r."1"                      # => foo
```

키의 대소문자를 구분하고 싶지 않을 때는 멤버 뒤에 `!`를 붙인다.

```nu
let person = {Name: "Sam"}
$person.name!               # => Sam
```

### 없는 값에 접근하기: 오류와 ?

기본적으로 없는 열이나 행에 접근하면 오류가 난다.

```nu
let cfg = {server: {host: "localhost", port: 8080}, tags: [web api]}
$cfg.server.user
# => Error: 열을 찾을 수 없음 (Cannot find column ...)
$cfg.tags.5
# => Error: 인덱스가 범위를 벗어남
```

오류 문구는 버전에 따라 조금 다를 수 있다. 값이 없을 수도 있다는 것을 알고 있을 때는 경로 멤버 뒤에 `?`를 붙인다. 이를 선택적(optional) 접근이라 하며, 없으면 오류 대신 `null`을 돌려준다.

```nu
$cfg.server.port?                  # => 8080
$cfg.server.user?                  # (아무것도 출력되지 않음 = null)
$cfg.server.user? | describe       # => nothing
$cfg.server.user? == null          # => true
$cfg.tags.5?                       # => null
```

`null`은 "값 없음"을 나타내는 값이고 타입 이름은 `nothing`이다. 셸은 `null`을 출력창에 아무것도 표시하지 않으므로, 확인하려면 `describe`나 `== null`을 쓴다. 값이 없을 때 대체값을 쓰려면 `default`를 이어 붙인다.

```nu
$cfg.server.user? | default "guest"     # => guest
$cfg.server.port? | default 80           # => 8080   (값이 있으면 그대로)
```

테이블에서 일부 행에만 열이 있는 경우에는 `get`의 `--optional`(`-o`) 플래그가 경로의 모든 멤버를 선택적으로 만든다.

```nu
[{a: 1} {b: 2}] | get -o a
# => 첫 번째 행은 1, 두 번째 행은 비어 있음(null)
```

**오해 교정.** `?`는 오류를 숨기는 만능 장치가 아니다. 없어도 되는 값에만 쓴다. 반드시 있어야 하는 값에 `?`를 붙이면 오타가 오류가 아니라 `null`로 조용히 흘러간다. 필수 값은 `?` 없이 두어 빨리 실패하게 하는 편이 낫다.

### get 과 select 의 차이

`get`은 경로가 가리키는 값 자체를 돌려주고, `select`는 그 부분을 담은 데이터 구조를 돌려준다.

```nu
let t = [[name age]; [kim 30] [lee 25]]
$t | get 1            # => {name: lee, age: 25}        레코드(값 자체)
$t | select 1         # => 1행짜리 테이블(구조 유지)
$t | get name         # => [kim, lee]                 리스트
$t | select name      # => name 열 하나를 가진 테이블
```

값 자체가 필요하면 `get`(또는 `$t.name`), 열을 골라 테이블로 계속 가공하려면 `select`를 쓴다. 4단원에서 `select name pid mem`으로 열을 골랐던 것이 후자다.

### 변수에 담긴 키로 접근하기

키 이름이 변수에 들어 있을 때는 `.` 경로 대신 `get`에 변수를 넘긴다.

```nu
let key = "port"
$cfg.server | get $key        # => 8080
```

경로 자체를 값으로 만들 수도 있다. `$.2` 같은 셀 경로 리터럴을 변수에 담아 `get`에 넘기면 된다.

```nu
let cp = $.2
[foo bar goo glue] | get $cp   # => goo
```

**판단 기준.** 변수 안으로 들어갈 때는 `$변수.경로`, 파이프라인 결과에서는 `get`이나 `(명령).경로`를 쓴다. 없을 수도 있는 값만 `?`를 붙이고 `default`로 대체값을 준다.

## 5.9 자주 만나는 오류와 해결법

Nushell의 오류는 "무엇이 왜 틀렸는지"를 설명하도록 만들어져 있다. 읽는 순서는 정해져 있다. 첫 줄의 코드(`nu::parser::...`)나 제목이 오류의 종류를 말하고, 화살표가 가리키는 위치가 문제의 지점이며, 마지막의 `help:` 줄이 해결 방향을 알려 준다. 아래는 이 단원 범위에서 가장 흔한 경우다.

| 증상(메시지) | 원인 | 해결 |
| --- | --- | --- |
| `assignment_requires_mutable_variable`, "Assignment to an immutable variable." | `let` 변수에 `$x = ...`로 대입했다. | 값이 바뀌어야 하면 `mut`로 선언하고, 새 값이면 `let`으로 다시 선언한다. |
| "Capture of mutable variable." | `each`, `reduce` 같은 클로저 안에서 `mut` 변수를 바꿨다. | `for`나 `while` 블록으로 바꾸거나 `reduce`, `math sum`, `length`로 표현한다. |
| "Variable not found." | 이름 오타, 선언 전에 사용, 블록 밖에서 안쪽 변수 사용, `unlet` 후 사용. | 스코프(선언된 `{ }`의 바깥인지)와 철자를 확인한다. |
| "The '-' operator does not work on values of type 'string'." | 문자열에 산술 연산을 했다. | `into int`, `into float`으로 먼저 변환한다. |
| 정수 변수의 `$x /= 2` 실패 | `/`는 항상 float을 돌려주는데 변수가 int다. | `$x = $x // 2`를 쓴다. |
| `let my-var = 1`이 파싱 오류 | 변수 이름에 `-`를 썼다. | `my_var`처럼 밑줄을 쓴다. |
| `if $x = 5`가 오류 | 비교(`==`) 자리에 대입(`=`)을 썼다. | `if $x == 5`로 고친다. |
| `$crew[2]`가 동작하지 않음 | 다른 언어의 대괄호 접근을 썼다. | `$crew.2`처럼 점으로 쓴다. |
| 열을 찾을 수 없다는 오류, 인덱스 범위 오류 | 없는 키나 인덱스에 접근했다. | 없을 수 있는 값이면 `$rec.key?`로 접근하고 `default`로 대체값을 준다. |
| `$"합계 (5건)"`이 오류 | 보간에서 괄호는 항상 식이다. | 문자 그대로의 괄호는 `\(`로 쓴다. |
| `source $path`가 거부됨 | `let` 변수는 파싱 시점에 값을 알 수 없다. | `const path = '...'`로 선언한다. |
| `"a.b" =~ "a.b"`가 `axb`에도 true | `.`는 정규식에서 임의의 한 글자다. | 글자 그대로 찾을 때는 `in`/`has`나 `\.`를 쓴다. |

### 흔한 오해 몇 가지

- **변수 앞의 `$`를 빠뜨린 경우.** `count`처럼 `$` 없이 쓰면 변수가 아니라 명령 이름이나 문자열로 읽힌다. 선언(`let count`, `mut count`)에서만 `$`가 필요 없고, 값을 읽거나 대입할 때는 `$count`를 쓴다.
- **변수는 파이프라인 안에서 바뀌지 않는다.** `let`은 값을 저장할 뿐이고, 같은 이름을 `let`으로 다시 선언한 것은 수정이 아니라 새 변수(섀도잉)다.
- **`mut`가 있으면 어디서든 바꿀 수 있다고 생각하는 경우.** 블록(`for`, `if`, `while`) 안에서는 바꿀 수 있지만 클로저 안에서는 바꿀 수 없다.
- **문자열 `"5"`와 숫자 5를 같다고 보는 경우.** `"5" == 5`는 같은 값이 아니다. 비교하기 전에 `into int`로 맞춘다.

### 디버깅 요령

값이 예상과 다를 때는 세 가지를 순서대로 해 본다. 먼저 `describe`로 타입을 확인한다(`$x | describe`). 그다음 긴 식을 괄호로 쪼개 한 조각씩 실행해 어디서 값이 달라지는지 본다. 마지막으로 스크립트 안에서는 `print $x`로 중간 값을 찍어 본다. 모르는 명령은 `help 명령이름`으로 시그니처와 예제를 먼저 본다.

```nu
let raw = "42"
$raw | describe              # => string
($raw | into int) | describe # => int
print $raw
help into int                # 변환 명령의 사용법과 예제
```

## 5.10 실습 과제와 해설

먼저 풀어 보고 해설을 열어 보길 권한다. 출력 모양은 환경에 따라 조금 다를 수 있으니 값이 맞는지를 기준으로 확인한다.

### 과제 1 (목차 과제): 레코드 갱신과 요약 문장

`mut` 레코드 변수를 만들어 필드를 갱신하고, 문자열 보간으로 요약 문장을 출력한다.

```nu
mut user = {name: "kim", age: 30, city: "Seoul"}
$user = ($user | update age { $in + 1 })
$user = ($user | update city "Busan")
print $"($user.name)님은 ($user.age)세이고 ($user.city)에 삽니다."
# => kim님은 31세이고 Busan에 삽니다.
```

해설. 1행은 레코드를 `mut` 변수에 담는다. 2행의 `update age { $in + 1 }`은 `age` 필드의 현재 값(`$in`)에 1을 더한 새 레코드를 만들고, 그 결과를 `$user`에 다시 대입한다. 3행은 클로저 대신 값을 바로 넘겨 `city`를 교체한다. 4행의 보간은 `($user.age)`처럼 괄호 안에서 필드를 꺼낸다. 이 변수를 `let`으로 선언했다면 2행에서 `assignment_requires_mutable_variable` 오류가 난다.

### 과제 2: 변수와 산술 연산

단가 12000원짜리 물건을 3개 사고 세금 10퍼센트를 더한 합계를 출력한다. 모두 정수로 계산한다.

```nu
let price = 12000
let qty = 3
let subtotal = $price * $qty
let tax = $subtotal // 10
let total = $subtotal + $tax
print $"소계 ($subtotal)원, 세금 ($tax)원, 합계 ($total)원"
# => 소계 36000원, 세금 3600원, 합계 39600원
```

해설. `/`로 나누면 결과가 float(`3600.0`)이 되므로, 정수 결과를 원하면 `//`를 쓴다. 각 값은 한 번 계산하면 바뀌지 않으므로 전부 `let`이다. `mut`가 필요 없는 것이 정상이다.

### 과제 3: 범위와 누적

1부터 100까지 숫자 중 3의 배수의 합을 두 가지 방식으로 구한다. 6단원 과제에서는 `reduce`로 한 번 더 구한다.

```nu
# 방식 A: mut + for 블록
mut sum = 0
for n in 1..100 {
  if $n mod 3 == 0 { $sum += $n }
}
print $sum
# => 1683

# 방식 B: 변수 없이 파이프라인만
1..100 | where {|n| $n mod 3 == 0} | math sum
# => 1683
```

해설. 방식 A에서 `$sum`을 바꾸는 곳은 `for`의 블록과 `if`의 블록이라 허용된다. 같은 로직을 `each`의 클로저 안에서 하면 "Capture of mutable variable." 오류가 난다. 방식 B는 `mut` 없이 같은 결과를 내며, 공식 책이 권하는 스타일이다. 검산하면 3의 배수는 3×1부터 3×33까지이므로 3×(33×34÷2)=1683이다.

### 과제 4: 없을 수 있는 값

일부 서버에는 `port`가 없다. 없으면 0으로 처리해 `이름:포트` 문자열 목록을 만든다.

```nu
let servers = [
  {name: "web1", port: 80}
  {name: "web2"}
  {name: "db1", port: 5432}
]
$servers | each {|s| $"($s.name):($s.port? | default 0)"}
# => [web1:80, web2:0, db1:5432]
```

해설. `$s.port?`는 키가 없으면 오류 대신 `null`을 돌려주고, `| default 0`이 `null`을 0으로 바꾼다. 보간의 괄호 안에서 파이프라인을 써도 된다. `?`를 빼면 두 번째 행에서 열을 찾을 수 없다는 오류가 난다.

### 과제 5: 오류 고치기

다음 세 코드는 모두 오류가 난다. 이유와 수정안을 말해 본다.

```nu
# (a)
let total = 0
for n in 1..3 { $total += $n }

# (b)
mut n = 0
[1 2 3] | each { $n += 1 }

# (c)
$"합계: (3건)"
```

해설. (a)는 `let` 변수에 대입했다. `mut total = 0`으로 선언해야 한다. (b)는 클로저 안에서 `mut` 변수를 바꿨다. 개수만 필요하면 `[1 2 3] | length`, 누적이 필요하면 `for` 블록을 쓴다. (c)는 괄호 안의 `3건`을 식으로 해석하려다 실패한다. `"합계: \(3건)"`처럼 여는 괄호를 이스케이프한다.

### 과제 6: 우선순위 손으로 계산하기

실행하기 전에 결과를 예측한다.

```nu
1 + 2 * 3 - 4 / 2
10 // 3 + 10 mod 3
not true and false or true
```

해설. 첫 식은 곱셈과 나눗셈이 먼저이므로 `1 + 6 - 2.0`이고, `/`가 float을 돌려주므로 결과는 `5.0`이다. 둘째 식은 `3 + 1`이라 `4`다. 셋째 식은 `not`이 `and`보다, `and`가 `or`보다 먼저이므로 `((not true) and false) or true`이고 결과는 `true`다.

### 확장 과제: 폴더 요약 한 줄 출력

현재 폴더의 파일 개수, 전체 크기, 가장 큰 항목의 이름을 한 문장으로 출력해 본다. 이 단원의 변수, 서브표현식, 보간, 셀 경로를 모두 쓴다.

```nu
let files = (ls)
let total_size = ($files | get size | math sum)
let biggest = ($files | sort-by size | last)
print $"항목 ($files | length)개, 전체 ($total_size), 가장 큰 항목: ($biggest.name)"
```

빈 폴더에서는 `last`에 줄 값이 없어 오류가 날 수 있다. 그 경우에 어떻게 처리할지는 6단원의 `if`와 `try`로 다시 풀어 본다.

### 이 단원을 마쳤는지 점검하기

- `let`, `mut`, `const`를 각각 언제 쓰는지 한 문장씩 말할 수 있다.
- `"Capture of mutable variable."`가 뜨면 왜 그런지, 어떻게 고치는지 설명할 수 있다.
- `/`와 `//`의 결과 타입이 다르다는 것을 알고 있다.
- 보간 문자열에서 괄호를 그대로 출력하는 방법을 안다.
- `$rec.key`와 `$rec.key?`의 동작 차이를 설명할 수 있다.

## 5.11 정리, 다음 단원, 출처

### 한 장 요약

| 하고 싶은 일 | 문법 | 기억할 점 |
| --- | --- | --- |
| 값에 이름 붙이기 | `let x = 1` | 기본 선택, 변경 불가 |
| 값을 바꿔 가며 쓰기 | `mut x = 1`, `$x += 1` | `for`, `while`, `if` 블록 안에서만 변경 가능 |
| 파싱 시점에 확정되는 값 | `const p = 'a.nu'` | `source`, `use` 인자에 필요 |
| 나눗셈 | `7 / 2`, `7 // 2`, `7 mod 3` | `/`는 항상 float, `//`는 정수 |
| 포함 검사 | `3 in [1 2 3]`, `[1 2 3] has 3` | 방향만 반대, 정규식 아님 |
| 패턴 검사 | `"abc" =~ '^a'` | 부분 일치, 대소문자 구분 |
| 문장에 값 끼우기 | `$"이름: ($name)"` | 괄호는 항상 식, 문자 괄호는 `\(` |
| 숫자 범위 | `1..5`, `1..<5`, `0..2..10` | 기본은 끝 값 포함, `..<`는 제외 |
| 값 꺼내기 | `$rec.key`, `$list.0`, `$t.0.name` | 인덱스는 0부터 |
| 없을 수 있는 값 | `$rec.key?` 와 `default` | 없으면 오류 대신 `null` |

### 판단 기준 다섯 가지

1. 새 값에는 `let`을 쓰고, 반복 블록에서 누적해야 할 때만 `mut`를 쓴다. 클로저 안에서 바꾸고 싶어지면 `reduce`나 `math sum` 같은 명령으로 표현할 수 있는지 먼저 본다.
2. 타입이 다른 값은 연산자가 섞어 주지 않는다. `into int`, `into string`, 문자열 보간으로 먼저 맞춘다.
3. 정수가 필요하면 `//`, 소수가 필요하면 `/`를 쓰고, 순서가 헷갈리는 식은 괄호로 쓴다.
4. 정확한 값 확인은 `in`과 `has`, 앞뒤 확인은 `starts-with`와 `ends-with`, 복잡한 규칙에만 `=~`를 쓴다.
5. 있어야 하는 값은 `?` 없이 접근해 빨리 실패하게 하고, 없을 수 있는 값만 `?`와 `default`로 처리한다.

### 다음 단원과의 연결

- **6단원 제어 흐름과 클로저.** 이 단원에서 "블록은 바꿀 수 있고 클로저는 바꿀 수 없다"고 배운 구분이 `if`, `for`, `each`, `reduce`의 동작을 이해하는 열쇠다. `$in`과 `try`/`catch`도 6단원에서 다룬다.
- **7단원 데이터 입출력과 변환.** 이번에 맛본 `into int`가 파일에서 읽은 값을 원하는 타입으로 바꾸는 핵심 도구가 된다.
- **8단원 커스텀 명령어.** 변수 선언과 타입 어노테이션이 `def`의 인자와 입출력 시그니처로 확장된다.
- **12단원 함수형 패턴과 성능.** `mut`와 반복문 방식, 파이프라인 방식의 속도 차이를 `timeit`으로 직접 잰다.

### 확인 범위와 한계

문법은 아래 공식 페이지를 2026-10-29에 열어 확인했다. 다음 항목은 열어 본 공식 페이지에서 확인하지 못했거나 작성 환경에서 실행해 보지 못했으니 직접 실행해 확인하길 권한다.

- `mut` 레코드의 필드에 직접 대입하는 문법(`$user.age = 31`). 이 가이드는 확인된 `update`, `merge`를 썼다.
- `slice`, `str upcase`, `str downcase`, `take`를 이 가이드의 용법대로 쓴 예제의 출력. `take`는 범위 페이지에 예가 있다.
- 모든 `# =>` 출력은 공식 페이지의 예제와 규칙에서 옮기거나 유추한 값이며, 이 환경에 `nu`가 없어 실행해 보지 못했다.
- 블록과 클로저의 `mut` 변수 규칙 중 `if` 블록 예제는 검색 결과로만 확인했다.
