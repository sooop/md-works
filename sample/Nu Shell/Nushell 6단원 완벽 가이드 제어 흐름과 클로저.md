# Nushell 6단원 완벽 가이드: 제어 흐름과 클로저

Oct 29, 2026 · @KWON BONG SOO

## 1. 이 단원에서 배우는 것

6단원의 핵심은 하나입니다. Nushell에서 `if`, `match`, `each`, `reduce`, `try`는 모두 값을 돌려주는 표현식이고, `for`, `while`, `loop`만 값을 돌려주지 않는 문장입니다. 이 차이를 알면 "어떤 반복 도구를 언제 쓰는가"와 "왜 어떤 코드는 mut 변수를 못 바꾸는가"가 한 번에 설명됩니다.

이 가이드를 읽고 나면 다음을 할 수 있습니다.

- 조건 분기를 `if`/`else`와 `match`로 쓰고, 결과를 변수나 파이프라인에 바로 연결한다.
- `for`, `while`, `loop`와 `each`, `reduce`를 상황에 맞게 고른다.
- 클로저 `{|x| ... }`를 직접 쓰고, `$in`과 명시적 매개변수 중 무엇이 나은지 판단한다.
- `try`/`catch`/`finally`와 `error make`로 실패를 처리하거나 직접 만든다.
- 클로저가 `mut` 변수를 바꾸지 못할 때 `reduce`나 `for`로 바꿔 쓴다.

전제는 5단원(변수, 연산자, 문자열 보간)이며, 가정한 독자 수준은 변수와 조건문 개념을 아는 초중급입니다. 문법은 공식 Nushell 책과 명령어 문서의 현재 판으로 확인했습니다. 이 작업 환경에는 `nu`가 설치되어 있지 않아 예제를 직접 실행하지는 못했고, 출력 주석은 공식 문서의 예제와 동작 설명을 근거로 적었습니다. 학습 환경에서 `version`으로 버전을 확인하고 예제를 직접 돌려 보세요.

### 두 계열의 반복 도구

Nushell에는 반복 도구가 두 계열 있습니다. 어느 쪽인지에 따라 값 반환, 파이프 사용, 외부 `mut` 변수 수정 가능 여부가 갈립니다.

| 계열 | 명령 | 값을 반환하는가 | 파이프에 연결 | 외부 mut 변수 수정 |
| --- | --- | --- | --- | --- |
| 문장 | `for`, `while`, `loop` | 아니오 | 불가(구문 오류) | 가능 |
| 표현식(블록) | `if`, `match`, `try` | 예 | 가능 | 가능 |
| 표현식(클로저) | `each`, `reduce`, `where` | 예 | 가능 | 불가(컴파일 오류) |

이 표를 묶는 원리는 한 줄입니다. 파이프라인 안에서 값을 흘려보내는 도구는 클로저를 쓰고, 클로저는 바깥의 `mut` 변수를 붙잡지 못합니다. 반대로 변수를 하나씩 갱신하는 반복은 문장 계열의 몫입니다. 이 원리는 7장(클로저)과 9장(실수와 선택 기준)에서 다시 다룹니다.

## 2. if / else: 값을 돌려주는 분기

`if`는 문장이 아니라 표현식이므로, 선택된 블록의 마지막 값이 곧 `if` 전체의 값이 됩니다. 그래서 결과를 변수에 담거나 파이프라인에 이어 붙일 수 있습니다.

### 기본 문법

```nu
if <조건> { <참일 때 실행> }
if <조건> { <참> } else { <거짓> }
if <조건1> { <A> } else if <조건2> { <B> } else { <C> }
```

| 요소 | 설명 |
| --- | --- |
| `<조건>` | 반드시 bool 값이어야 합니다. 0, 빈 문자열, 빈 리스트가 거짓으로 자동 변환되지 않습니다. |
| `{ ... }` | 블록입니다. 마지막 식의 값이 `if`의 값이 되고, 바깥의 `mut` 변수를 바꿀 수 있습니다. |
| `else if` | 조건을 위에서 아래로 차례로 검사하고, 처음 참인 분기만 실행합니다. |
| `} else {` | `}`와 `else`를 같은 줄에 쓰는 것을 관례로 삼으세요. 줄을 나누면 환경에 따라 구문 오류가 날 수 있습니다. |

### 예제 1: 가장 기본적인 형태

```nu
let x = 0
if $x > 0 { 'positive' } else if $x == 0 { 'zero' } else { 'negative' }
# => zero
```

`$x > 0`은 거짓이므로 건너뛰고, `$x == 0`이 참이므로 `'zero'`가 선택됩니다. 마지막 `else`는 앞의 모든 조건이 거짓일 때만 실행됩니다.

### 예제 2: if의 결과를 변수에 담기

```nu
let score = 85
let grade = if $score >= 90 { 'A' } else if $score >= 80 { 'B' } else { 'C' }
$grade
# => B
```

다른 언어의 삼항 연산자 자리를 `if` 표현식이 대신합니다. `let` 뒤에서 `if`를 쓸 때는 모든 분기가 값을 내도록 `else`까지 쓰는 편이 안전합니다.

### 예제 3: else를 빼면 null이 돌아온다

```nu
let r = if false { 'yes' }
$r
# => null (표시상 빈 값)
```

`else`가 없고 조건이 거짓이면 `if`는 `null`을 반환합니다. 이 값을 이어서 `str length` 같은 명령에 넘기면 타입 오류가 나므로, 값을 쓸 목적이라면 `else`를 반드시 붙입니다.

### 예제 4: 파이프 입력을 $in으로 받아 분기하기

```nu
'foo' | if $in == 'foo' { 1 } else { 0 } | $in + 2
# => 3
```

`if`는 파이프의 앞 단계 값을 `$in`으로 받을 수 있고, 그 결과를 다음 단계로 넘깁니다. `$in + 2`는 마지막 단계에서 `1 + 2`를 계산합니다.

### 예제 5: 조건에 파이프라인이 들어갈 때는 괄호로 감싼다

```nu
let names = [kim lee park]
if ($names | length) > 2 { 'many' } else { 'few' }
# => many
```

조건식 안에서 파이프를 쓰려면 `($names | length)`처럼 소괄호로 서브표현식을 만들어야 비교 연산자와 이어집니다. 괄호가 없으면 파서가 `length` 뒤의 `> 2`를 의도와 다르게 해석해 오류가 날 수 있으므로 괄호로 범위를 분명히 하는 것이 안전합니다.

### 예제 6: 논리 연산자와 포함 연산자 조합

```nu
let ext = 'md'
let size = 2kb
if $ext in [md txt] and $size < 10kb { 'small text file' } else { 'other' }
# => small text file
```

`in`, `and`, `or`, `not`은 5단원에서 배운 연산자입니다. `$size`는 filesize 타입이라 `10kb`와 단위를 붙여 직접 비교할 수 있습니다.

### 예제 7: each 안에서 행마다 분류하기

```nu
ls | each {|f| if $f.size > 1mb { 'big' } else { 'small' } }
# => [small, small, big, ...]  (파일 개수만큼의 문자열 리스트)
```

`ls`가 만드는 테이블의 각 행을 `$f`로 받아 크기에 따라 분류합니다. 결과가 값 목록이므로 이름까지 함께 보려면 `ls | insert kind {|f| ...}`처럼 열을 추가하는 방법을 쓰면 됩니다.

### 오해 교정

- `if`는 값을 반환하므로 `if ... { print 'a' }`처럼 출력만 하는 분기를 쓰면 반환값은 `null`입니다. 이 `null`이 REPL에 그대로 표시될 수 있는데 오류가 아닙니다.
- `if` 블록은 클로저가 아니라 일반 블록입니다. 그래서 블록 안에서 `$count = $count + 1`처럼 `mut` 변수를 바꿀 수 있습니다.
- 같은 변수에 대한 여러 조건은 `else if`를 길게 잇기보다 `match`(3장)가 읽기 쉽습니다.

## 3. match: 값의 모양으로 분기하기

`match`는 하나의 값을 위에서부터 패턴과 차례로 비교해, 처음 맞는 분기의 결과를 돌려주는 표현식입니다. 같은 변수를 `else if`로 여러 번 비교하는 코드가 길어질 때, 그리고 레코드나 리스트의 모양으로 분기하고 싶을 때 `match`가 더 읽기 쉽습니다.

### 기본 문법

```nu
match <값> {
    <패턴1> => <결과1>,
    <패턴2> => { <여러 문장의 블록> },
    _ => <나머지 모두>
}
```

| 요소 | 설명 |
| --- | --- |
| `<값>` | 비교 대상입니다. 변수, 리터럴, 서브표현식 모두 가능합니다. |
| `=>` | 패턴과 결과를 잇습니다. 결과 자리에는 값, 표현식, `{ ... }` 블록을 쓸 수 있습니다. |
| `_` | 와일드카드입니다. 어떤 값이든 맞으므로 마지막 분기에 둡니다. |
| 분기 구분 | 쉼표나 줄바꿈으로 나눕니다. |

### 예제 1: 값 비교와 와일드카드

```nu
match 3 {
    1 => 'one',
    2 => { let w = 'w'; 't' + $w + 'o' },
    3 => 'three',
    4 => 'four'
}
# => three

match 7 { 1 => 'one', _ => 'other number' }
# => other number
```

두 번째 분기처럼 결과 자리에 블록을 쓰면 `let`을 포함한 여러 문장을 실행할 수 있고, 블록의 마지막 값이 결과가 됩니다. 어떤 분기도 맞지 않을 경우를 대비해 `_`를 마지막에 두는 습관을 들이세요.

### 예제 2: 여러 값을 한 분기로 묶기

```nu
let code = 404
match $code {
    200 | 201 | 204 => 'success',
    301 | 302 => 'redirect',
    404 => 'not found',
    _ => 'other'
}
# => not found
```

`|`로 이어 쓴 패턴은 "둘 중 하나"라는 뜻입니다. 같은 처리를 하는 값을 분기마다 반복하지 않아도 됩니다.

### 예제 3: 문자열과 null 분기

```nu
def describe-env [name: string] {
    match ($env | get -o $name) {
        null => $"($name) is not set",
        $v => $"($name) = ($v)"
    }
}
describe-env HOME
# => HOME = /home/...  (설정된 값에 따라 다름)
```

`null` 자체도 패턴이 됩니다. `$v`처럼 변수 이름만 쓰면 어떤 값이든 맞으면서 그 값이 `$v`에 바인딩되므로, `null` 분기 뒤의 "나머지 전부"를 변수로 받을 때 유용합니다. `get -o`는 없는 키에 오류 대신 `null`을 돌려주는 옵션입니다.

### 예제 4: 레코드 패턴

```nu
let foo = { name: 'bar', count: 7 }
match $foo {
    { name: 'bar', count: $it } => ($it + 3),
    { name: _, count: $it } => ($it + 7),
    _ => 1
}
# => 10
```

레코드 패턴은 필드 이름과 값으로 모양을 맞춥니다. 첫 분기는 `name`이 `'bar'`인 레코드만 받고 `count` 값을 `$it`에 묶습니다. 두 번째의 `name: _`는 이름이 무엇이든 맞는다는 뜻입니다. 결과 자리의 `($it + 3)`처럼 식은 소괄호로 감쌉니다.

### 예제 5: 리스트 패턴

```nu
let steps = [build test done]
match $steps {
    [] => 'nothing to do',
    [.., 'done'] => 'finished',
    [$current, ..] => $"running ($current)"
}
# => finished
```

`[]`는 빈 리스트, `..`는 앞, 중간, 끝의 임의 개수 항목을 뜻합니다. `[.., 'done']`은 마지막 항목이 `'done'`인 리스트에 맞고, `[$current, ..]`는 첫 항목을 `$current`에 묶습니다. 분기는 위에서부터 검사하므로 구체적인 패턴을 위에 둡니다. 순서를 바꿔 `[$current, ..]`를 먼저 두면 항상 그쪽이 선택됩니다.

### 예제 6: 가드(guard)로 조건 덧붙이기

```nu
match { name: 'bar', count: 7 } {
    { name: 'bar', count: $it } if $it < 5 => ($it + 3),
    { name: 'bar', count: $it } if $it >= 5 => ($it + 7),
    _ => 1
}
# => 14
```

패턴 뒤, `=>` 앞에 `if <조건>`을 붙이면 패턴이 맞고 조건도 참일 때만 그 분기가 선택됩니다. 범위 비교처럼 패턴만으로 표현하기 어려운 조건은 가드로 처리하세요. 아래는 숫자 구간 분류의 예입니다.

```nu
def size-label [n: int] {
    match $n {
        $x if $x < 10 => 'small',
        $x if $x < 100 => 'medium',
        _ => 'large'
    }
}
size-label 42
# => medium
```

### if/else와 match 중 무엇을 쓸까

- 참/거짓 두 갈래이거나 조건이 서로 다른 변수에 걸려 있으면 `if`/`else`.
- 한 값의 여러 경우, 값의 모양(레코드, 리스트), 같은 처리를 하는 값 묶음이면 `match`.

위 두 기준을 요약하면, 조건이 "값에 대한 질문"이면 `if`, "값의 정체"이면 `match`입니다.

## 4. for, while, loop: 문장으로 반복하기

`for`, `while`, `loop`는 값을 돌려주지 않는 문장입니다. 대신 본문이 블록이라서 바깥의 `mut` 변수를 자유롭게 갱신할 수 있습니다. 상태를 하나씩 바꿔 가며 처리하는 반복은 이 계열이 맞습니다.

### 문법 한눈에 보기

| 명령 | 문법 | 언제 끝나는가 |
| --- | --- | --- |
| `for` | `for <변수> in <리스트나 범위> { ... }` | 모든 항목을 소진하면 끝납니다. |
| `while` | `while <조건> { ... }` | 조건이 거짓이 되면 끝납니다. |
| `loop` | `loop { ... }` | `break`를 만날 때까지 무한 반복합니다. |
| `break` | 반복 안에서 단독으로 사용 | 반복을 즉시 벗어납니다. |
| `continue` | 반복 안에서 단독으로 사용 | 이번 회차의 나머지를 건너뛰고 다음 회차로 갑니다. |

### 예제 1: for의 기본형과 값을 출력하는 이유

```nu
for x in [1 2 3] { $x * $x | print }
# 1
# 4
# 9
```

`for`는 값을 반환하지 않으므로 계산 결과가 자동으로 화면에 나오지 않습니다. 결과를 보려면 `print`를 명시해야 합니다. 같은 일을 `[1 2 3] | each { $in * $in }`로 쓰면 `print` 없이 `[1, 4, 9]` 리스트가 결과로 나옵니다.

### 예제 2: 범위와 break

```nu
for x in 1..10 {
    if $x > 3 { break }
    print $x
}
# 1
# 2
# 3
```

`1..10`은 1부터 10까지 포함하는 범위입니다. `$x`가 4가 되는 순간 `break`가 반복 전체를 끝내고 `for` 다음 문장으로 넘어갑니다.

### 예제 3: for로 결과를 모으기 (mut 변수 갱신)

```nu
mut result = []
for it in [1 2 3] {
    $result = ($result | append ($it + 1))
}
$result
# => [2, 3, 4]
```

빈 리스트 `$result`를 `mut`로 선언하고, 회차마다 `append`로 새 리스트를 만들어 다시 대입합니다. `append`는 원본을 바꾸지 않고 새 리스트를 돌려주므로 반드시 `$result = ...`로 되받아야 합니다. 이 모양이 `for`의 대표 용도이고, 파이프 방식이라면 `[1 2 3] | each { $in + 1 }` 한 줄로 끝납니다.

### 예제 4: 인덱스가 필요할 때는 enumerate

```nu
for row in ([a b c] | enumerate) {
    print $"($row.index): ($row.item)"
}
# 0: a
# 1: b
# 2: c
```

`enumerate`는 각 항목을 `{index: 0, item: 'a'}` 모양의 레코드로 바꿉니다. `for` 안에서 `$row.index`와 `$row.item`으로 접근합니다. 리스트 뒤에 파이프가 붙는 표현은 소괄호로 감싸야 `in` 자리에 들어갑니다.

### 예제 5: while로 조건이 바뀔 때까지 반복

```nu
mut x = 0
while $x < 10 { $x = $x + 1 }
$x
# => 10
```

반복 횟수를 미리 알 수 없고 "어떤 조건이 만족될 때까지"가 기준일 때 씁니다. 본문에서 조건에 쓰인 변수를 반드시 바꿔야 무한 반복에 빠지지 않습니다.

### 예제 6: continue로 건너뛰기

```nu
mut x = -1
while $x <= 6 {
    $x = $x + 1
    if $x mod 3 == 0 { continue }
    print $x
}
# 1
# 2
# 4
# 5
```

`mod`는 나머지 연산자입니다. 3의 배수(0, 3, 6)일 때는 `continue`가 `print`를 건너뜁니다. 0부터 6까지 증가시키며 `$x`가 0, 3, 6인 회차의 출력이 빠집니다.

### 예제 7: loop와 break로 직접 종료 조건 만들기

```nu
mut x = 0
loop {
    if $x > 10 { break }
    $x = $x + 1
}
$x
# => 11
```

`loop`는 종료 조건을 본문 안에서 직접 판단합니다. 서버를 계속 감시하는 스크립트처럼 끝나지 않는 작업, 또는 종료 조건이 반복 중간에 있는 작업에 알맞습니다. 조건이 맨 앞에 있다면 `while`이 더 간결합니다.

### 예제 8: 반복 안에서 파일 처리하기

```nu
for f in (ls *.md) {
    if $f.size > 10kb {
        print $"($f.name) is large"
    }
}
```

`(ls *.md)`는 테이블을 만들고, `for`는 테이블의 행을 하나씩 레코드로 꺼냅니다. 이름과 크기만 필요하다면 `ls *.md | where size > 10kb | get name`이 훨씬 짧습니다. 부수 효과(출력, 파일 쓰기)가 목적일 때만 `for`를 선택하세요.

### 오해 교정

- `for` 결과를 파이프로 이을 수 없습니다. `for x in [1 2] { $x } | length`처럼 쓰면 키워드 위치 오류로 파싱이 실패합니다. 값을 이어서 쓰려면 `each`를 쓰세요.
- `break`와 `continue`는 `for`, `while`, `loop` 안에서만 의미가 있습니다. `each` 안의 클로저는 반복문의 본문이 아니므로 break로 반복을 끊는다고 기대하기 어렵고(설치 버전에서 확인하세요), 조건부 중단이 필요하면 `each while`, `take while`, `first` 같은 전용 명령을 찾아보세요.

## 5. each와 par-each: 파이프로 반복하기

`each`는 입력 리스트나 테이블의 항목마다 클로저를 실행하고, 각 결과를 모아 새 리스트로 돌려주는 표현식입니다. Nushell다운 반복의 기본 도구이며, 변환 결과가 파이프라인의 다음 단계로 흘러간다는 점이 `for`와 다릅니다.

### 문법

```nu
<입력> | each {|항목| <본문> }
<입력> | each { <본문에서 $in 사용> }
<입력> | each --keep-empty {|항목| ... }
<입력> | each --flatten {|항목| ... }
```

| 요소 | 설명 |
| --- | --- |
| `{\|e\| ... }` | 클로저입니다. `\|e\|` 자리의 `e`가 현재 항목을 받는 매개변수 이름입니다. |
| `$in` | 매개변수를 쓰지 않고 현재 항목을 파이프 입력으로 받는 방법입니다. |
| `--keep-empty` (`-k`) | 클로저가 `null`을 돌려준 항목도 결과에 남깁니다. |
| `--flatten` (`-f`) | 각 결과가 스트림이면 한 줄기로 이어 붙이고, 별도 값으로 모으지 않습니다. |

입력이 테이블이면 한 행이 하나의 레코드로 전달됩니다. 입력이 단일 값이면 그 값이 한 번 처리됩니다.

### 예제 1: 기본 변환

```nu
[1 2 3] | each {|e| 2 * $e }
# => [2, 4, 6]

[1 2 3] | each { $in + 1 }
# => [2, 3, 4]
```

같은 일을 `{|e| ...}`처럼 이름을 붙이는 방식과 `$in` 방식으로 썼습니다. 본문이 한 줄이면 `$in`이 짧고, 클로저 안에 또 다른 파이프나 중첩 클로저가 있으면 이름을 붙이는 쪽이 헷갈리지 않습니다.

### 예제 2: null을 돌려주면 결과에서 빠진다

```nu
[1 2 3 2] | each {|e| if $e == 2 { 'two' } }
# => [two, two]

[1 2 3] | each --keep-empty {|e| if $e == 2 { 'found 2!' } }
# => [null, found 2!, null]  (표시상 빈칸, 2번째 칸만 값이 있음)
```

`else` 없는 `if`가 `null`을 돌려주므로, `each`와 `if`를 조합하면 조건에 맞는 항목만 남기면서 변환하는 효과가 납니다. 다른 언어의 `filter_map`과 같습니다. 빈 칸까지 보존해 위치를 맞춰야 한다면 `--keep-empty`를 씁니다.

### 예제 3: 인덱스와 함께 처리하기

```nu
[1 2 3] | enumerate | each {|e|
    if $e.item == 2 { $"found 2 at ($e.index)!" }
}
# => [found 2 at 1!]
```

`enumerate`가 `{index, item}` 레코드를 만들고, 클로저는 `$e.item`과 `$e.index`로 둘 다 사용합니다. 위치 정보가 필요한 반복은 `for`가 아니라 이렇게 `enumerate`와 `each`로 이어 쓸 수 있습니다.

### 예제 4: 테이블의 행마다 처리하기

```nu
ls | each {|f| $"($f.name): ($f.size)" }
# => ["a.md: 1.2 KiB", "b.md: 800 B", ...]

ls | each {|f| { name: $f.name, kb: ($f.size / 1kb) } }
# => 이름과 KB 크기를 가진 레코드의 리스트(= 테이블)
```

클로저가 문자열을 돌려주면 문자열 리스트, 레코드를 돌려주면 레코드 리스트(테이블)가 됩니다. 두 번째 예에서 클로저 본문이 레코드 리터럴 `{ ... }`이므로, 바깥 `{ }`와 안쪽 `{ }`의 역할을 구분해서 읽어야 합니다. 열을 추가하는 것이 목적이라면 `insert`, `update`, `select`가 더 짧습니다.

### 예제 5: 부수 효과만 쓰는 each

```nu
1..3 | each { print $in }
# 1
# 2
# 3
# => 빈 리스트(empty list)
```

`print`는 값을 돌려주지 않으므로 `each`의 결과는 빈 리스트가 됩니다. 출력 목적이면 결과를 `| ignore`로 버리거나 `for`를 쓰는 편이 깔끔합니다.

### 예제 6: 여러 파일을 읽어 한 줄기로 합치기

```nu
ls *.txt | each --flatten {|f| open $f.name | lines } | find -i 'note: '
```

`--flatten`을 쓰면 각 파일의 줄 스트림이 파일 단위 리스트로 묶이지 않고 하나의 스트림으로 이어져서, 뒤의 `find`가 첫 결과를 기다리지 않고 바로 일할 수 있습니다.

### par-each: 병렬 버전

`par-each`는 `each`와 같은 문법으로 항목을 여러 스레드에 나눠 동시에 처리합니다.

| 옵션 | 설명 |
| --- | --- |
| `--threads` (`-t`) | 사용할 스레드 수를 지정합니다. |
| `--keep-order` (`-k`) | 결과를 입력 순서와 같게 유지합니다. |

```nu
[1 2 3] | par-each {|e| $e * 2 }
# => 2, 4, 6 (순서는 보장되지 않음)

[1 2 3] | par-each --keep-order {|e| $e * 2 }
# => [2, 4, 6]
```

기본값에서는 완료되는 순서대로 결과가 나오므로 입력 순서와 달라질 수 있습니다. 순서가 중요하면 `--keep-order`를 쓰거나, 뒤에서 `sort`로 정렬하세요.

`par-each`가 이득을 주는 경우는 항목마다 걸리는 시간이 길 때(네트워크 요청, 큰 파일 처리)입니다. 항목당 작업이 가벼우면 스레드 관리 비용이 더 커서 `each`가 빠를 수 있습니다. 실제 판단은 12단원의 `timeit`으로 측정해서 하세요. 클로저가 외부 상태를 바꾸는 코드도 병렬 환경에서는 예측할 수 없으니 순수 변환에만 쓰는 것이 안전합니다.

### 오해 교정

- `each`는 클로저이므로 바깥의 `mut` 변수를 바꿀 수 없습니다. 누적이 필요하면 `reduce`(6장)를 쓰거나 `for`로 바꿉니다.
- `each`의 결과를 버리고 싶지 않은 이상 마지막 식이 값을 내도록 쓰세요. 마지막에 `print`만 있으면 값이 없는 리스트가 나옵니다.
- 오류가 나면 `each`는 오류 메시지에 "원본 값" 라벨을 붙여 어떤 항목에서 실패했는지 보여 줍니다. `for`로 같은 오류가 나면 이 라벨이 없습니다.

## 6. reduce와 where: 누적하고 걸러내기

`reduce`는 리스트 전체를 하나의 값으로 접는 명령이고, `where`는 조건에 맞는 항목만 남기는 명령입니다. `each`가 항목마다 독립적으로 변환한다면, `reduce`는 이전 결과를 다음 항목에 넘기며 누적합니다. `mut` 변수를 바꿀 수 없는 클로저 안에서 "누적"을 표현하는 정식 방법이 `reduce`입니다.

### reduce 문법과 인자 순서

```nu
<입력> | reduce {|it, acc| <새 acc를 돌려주는 식> }
<입력> | reduce --fold <초기값> {|it, acc| ... }
```

| 요소 | 설명 |
| --- | --- |
| `it` | 현재 항목입니다. |
| `acc` | 지금까지의 누적값(accumulator)입니다. |
| `--fold` (`-f`) | 누적값의 초기값을 지정합니다. 생략하면 첫 항목이 초기값이 되고 둘째 항목부터 클로저가 실행됩니다. |
| 반환값 | 클로저가 돌려준 값이 다음 회차의 `acc`가 되고, 마지막 `acc`가 전체 결과입니다. |

가장 흔한 실수는 매개변수 순서입니다. 많은 언어와 달리 Nushell의 `reduce` 클로저는 `{|it, acc|}`로 항목이 먼저, 누적값이 나중입니다. 순서를 바꿔 쓰면 뺄셈, 문자열 이어 붙이기처럼 교환법칙이 성립하지 않는 연산에서 결과가 달라집니다.

### 예제 1: 합계와 초기값

```nu
[1 2 3 4] | reduce {|it, acc| $it + $acc }
# => 10

[1 2 3 4] | reduce --fold 10 {|it, acc| $acc + $it }
# => 20
```

첫 식은 초기값이 없어 `acc`가 1에서 시작해 `1+2`, `3+3`, `6+4`로 10이 됩니다. 두 번째 식은 `acc`가 10에서 시작하므로 10에 1, 2, 3, 4를 더한 20입니다.

### 예제 2: 연산 순서 확인 (뺄셈)

```nu
[1 2 3 4] | reduce {|it, acc| $acc - $it }
# => -8
```

`(((1 - 2) - 3) - 4)`와 같이 왼쪽에서 오른쪽으로 접힙니다. 순서가 헷갈리면 이 예제로 `acc`가 왼쪽 피연산자임을 확인하세요.

### 예제 3: 최댓값 찾기

```nu
[3 9 2 7] | reduce {|it, acc| if $it > $acc { $it } else { $acc } }
# => 9
```

회차마다 더 큰 쪽을 누적값으로 남기는 패턴입니다. 클로저 본문이 `if` 표현식 하나이고, 그 값이 곧 새 `acc`가 됩니다. 실무에서는 `math max`가 더 짧지만, 조건이 복잡한 선택 로직은 이 패턴으로 일반화됩니다.

### 예제 4: 범위에서 조건부로 누적하기

```nu
1..10 | reduce --fold 0 {|it, acc|
    if $it mod 2 == 0 { $acc + $it } else { $acc }
}
# => 30
```

짝수(2, 4, 6, 8, 10)만 더합니다. 조건이 거짓일 때도 반드시 `$acc`를 그대로 돌려줘야 누적값이 끊기지 않습니다. 이 `else { $acc }`를 빠뜨려 `null`이 되는 것이 `reduce`의 대표적인 버그입니다.

### 예제 5: 문자열 만들기와 레코드 병합

```nu
[ i o t ] | reduce --fold 'Arthur, King of the Britons' {|it, acc|
    $acc | str replace --all $it 'X'
}
# => ArXhur, KXng Xf Xhe BrXXXns

[{a: 1} {b: 2} {c: 3}] | reduce {|it| merge $it }
# => {a: 1, b: 2, c: 3}
```

첫 식은 누적값(문자열)에 항목마다 치환을 한 번씩 적용합니다. 둘째 식은 매개변수를 `it` 하나만 쓰는 형태로, 이때 누적값이 파이프 입력으로 들어와서 `merge $it`이 "누적값을 `$it`와 병합"이라는 뜻이 됩니다. 레코드를 하나로 합칠 때 자주 쓰는 모양입니다.

### 예제 6: 인덱스와 함께 누적하기

```nu
[8 7 6] | enumerate | reduce --fold 0 {|it, acc| $acc + $it.item + $it.index }
# => 24
```

`enumerate`로 `{index, item}` 레코드를 만든 뒤 항목값(8+7+6=21)과 인덱스(0+1+2=3)를 모두 더해 24가 됩니다.

### where: 조건으로 행 거르기

`where`는 두 가지 형태로 씁니다.

```nu
ls | where size > 1mb
ls | where {|f| $f.size > 1mb and $f.type == 'file' }
1..100 | where {|n| $n > 80 and $n < 86 }
# => [81, 82, 83, 84, 85]
```

| 형태 | 설명 |
| --- | --- |
| `where <열> <연산자> <값>` | 열 이름을 직접 쓰는 간단한 조건입니다. 4단원에서 배운 형태입니다. |
| `where {\|행\| <bool을 돌려주는 식> }` | 클로저 조건입니다. 여러 조건을 조합하거나 값 리스트처럼 열이 없는 입력을 거를 때 씁니다. |

### 선택 기준: each, reduce, where

- 항목마다 값을 바꿔 같은 개수의 결과가 필요하면 `each`.
- 조건에 맞는 항목만 남기려면 `where`.
- 여러 항목을 하나의 값(합계, 최댓값, 합쳐진 레코드)으로 접으려면 `reduce`.

세 명령 모두 클로저를 쓰므로 바깥 `mut` 변수를 바꾸지 못하며, `reduce`의 누적값이 그 역할을 대신합니다.

## 7. 클로저와 $in: 코드를 값처럼 다루기

클로저는 이름 없는 작은 함수 값입니다. 변수에 담고, 명령에 인자로 넘기고, 나중에 `do`로 실행할 수 있습니다. `each`, `where`, `reduce`가 받는 `{|x| ... }`가 모두 클로저입니다. 클로저를 이해하면 이 명령들이 "왜 mut 변수를 못 바꾸는지"와 "`$in`이 무엇인지"가 한꺼번에 풀립니다.

### 문법

```nu
{|매개변수1, 매개변수2| <본문> }      # 매개변수가 있는 클로저
{|a: int, b: int| <본문> }            # 타입을 붙인 매개변수
{|| <본문> }                          # 매개변수가 없는 클로저 (|| 는 생략 가능)
do <클로저> <인자1> <인자2>           # 클로저 실행
```

| 요소 | 설명 |
| --- | --- |
| `{\|a, b\| ...}` | 두 수직선 사이가 매개변수 목록입니다. 쉼표로 나눕니다. |
| 타입 표기 | `name: type` 형태로 매개변수에 타입을 붙일 수 있습니다. |
| `do` | 클로저를 실제로 실행하는 명령입니다. 뒤에 인자를 순서대로 넘깁니다. |
| 마지막 식 | 클로저는 본문의 마지막 식의 값을 돌려줍니다. |

### 예제 1: 만들고 실행하기

```nu
do {|a, b| $a + $b } 34 8
# => 42

do {|a: int, b: int| $a + $b } 34 8
# => 42

let add = {|a, b| $a + $b }
do $add 1 2
# => 3
```

클로저는 선언만으로는 실행되지 않습니다. 세 번째 묶음처럼 변수에 담아 두었다가 `do $add 1 2`로 호출합니다. 변수에 담은 클로저의 타입은 `closure`입니다.

### 예제 2: 매개변수 방식과 $in 방식

```nu
[1 2 3] | each {|num| $num * 10 }
# => [10, 20, 30]

[1 2 3] | each { $in * 10 }
# => [10, 20, 30]
```

두 식은 같은 결과를 냅니다. 명령이 클로저에게 현재 항목을 줄 때 매개변수로도, 파이프 입력(`$in`)으로도 받을 수 있기 때문입니다. 판단 기준은 다음과 같습니다.

- 본문이 짧고 항목을 한 번만 쓰면 `$in`.
- 항목을 여러 번 쓰거나 본문 안에 또 다른 파이프, 중첩 클로저가 있으면 이름 있는 매개변수.
- `reduce`처럼 값이 둘 이상(`it`, `acc`)이면 반드시 매개변수.

### 예제 3: $in은 파이프 단계마다 달라진다

```nu
[1 2 3] | each {
    let n = $in
    [$n ($n * $n)] | str join ':'
}
# => [1:1, 2:4, 3:9]
```

본문이 여러 단계의 파이프라면 `$in`은 그 단계의 입력을 가리켜 의미가 바뀝니다. 본문의 첫 줄에서 `let n = $in`으로 항목을 변수에 고정해 두면 이 혼동을 피할 수 있습니다.

### 예제 4: 변수를 붙잡는 클로저 (capture)

```nu
def create_greeter [ greeting: string ]: nothing -> closure {
    {|name| $"($greeting), ($name)" }
}

let greet = create_greeter 'Hello'
do $greet Dalija
# => Hello, Dalija

let greet = create_greeter 'Aloha'
do $greet Kai
# => Aloha, Kai
```

클로저는 만들어지는 시점에 주변의 `let` 변수와 명령 매개변수를 붙잡아(capture) 둡니다. `create_greeter`가 끝난 뒤에도 `$greeting`이 클로저 안에 남아 있습니다. 반환 타입 `nothing -> closure`는 입력 없이 클로저를 돌려준다는 시그니처로, 8단원에서 자세히 다룹니다.

### 예제 5: 클로저를 인자로 받는 명령

```nu
def apply-twice [f: closure, x: int] {
    do $f (do $f $x)
}
apply-twice {|n| $n * 2 } 5
# => 20
```

매개변수 타입을 `closure`로 선언하면 호출자가 동작을 넘길 수 있습니다. 같은 구조로 "정렬 기준", "변환 규칙" 같은 동작을 바깥에서 주입하는 명령을 만들 수 있습니다.

### 핵심 규칙: 클로저는 mut 변수를 붙잡지 못한다

```nu
mut total = 0
[1 2 3] | each {|n| $total = $total + $n }
# => Error: nu::parser::expected_keyword
# =>   Capture of mutable variable.
```

공식 문서는 이 제한을 규칙으로만 설명합니다. 클로저는 호출 시점이 호출받은 명령에 달려 있고 병렬로도 실행될 수 있으므로, 바뀌는 변수를 붙잡지 못하게 한 것으로 이해하면 편합니다. 컴파일 단계에서 막히는 오류이니 실행 전에 알아챌 수 있습니다. 해결 방법은 상황에 따라 세 가지입니다.

```nu
# 1) 누적이 목적이면 reduce
[1 2 3] | reduce --fold 0 {|n, acc| $acc + $n }
# => 6

# 2) 결과가 필요 없고 mut 갱신이 목적이면 for
mut total = 0
for n in [1 2 3] { $total = $total + $n }
$total
# => 6

# 3) 읽기만 하면 되는 값은 let으로 고정해서 붙잡기
mut base = 10
let snapshot = $base
[1 2] | each {|n| $n + $snapshot }
# => [11, 12]
```

주의할 점은 첫 번째 방식에서 `reduce`의 매개변수 순서가 `{|it, acc|}`라는 것입니다. 위 예제는 `{|n, acc|}`로 읽어야 하는데, 뜻은 "첫 이름이 항목, 둘째 이름이 누적값"이라 이름은 자유롭게 지어도 됩니다.

### 블록과 클로저의 차이

| 구분 | 어디에 쓰이는가 | 바깥 mut 변수 수정 | 매개변수 |
| --- | --- | --- | --- |
| 블록 | `if`, `else`, `match`, `for`, `while`, `loop`, `try` 본문 | 가능 | 없음 |
| 클로저 | `each`, `par-each`, `where`, `reduce`, `catch`와 `finally`의 인자 | 불가 | `{\|x\| ...}`로 받음 |

구분 기준은 "이 코드가 지금 이 자리에서 실행되는가, 아니면 다른 명령에게 맡겨 나중에 실행되는가"입니다. 지금 실행되면 블록, 맡기면 클로저입니다.

### 부록: 환경 변수와 재귀 한도

- 클로저에서 `$env`를 바꾸고 싶으면 `do --env`로 실행해야 호출자의 환경에 반영됩니다. 환경을 바꾸는 명령은 8단원의 `def --env`와 연결됩니다.
- 클로저 호출은 한 번마다 `$env.config.recursion_limit`(기본 50)에 계산됩니다. 클로저가 자신을 호출하는 재귀는 이 한도에서 오류로 멈춥니다.

## 8. try, catch, finally와 error make: 실패 다루기

Nushell의 오류는 발생하면 스크립트를 멈추고 메시지를 보여 줍니다. `try`는 그 오류를 붙잡아 계속 실행할 수 있게 하고, `error make`는 반대로 내가 직접 오류를 일으킵니다. 이 둘을 함께 쓰면 "실패해도 사용자에게 친절한 안내를 하고 끝나는 스크립트"를 만들 수 있습니다.

### try 문법

```nu
try { <시도할 코드> }
try { <시도> } catch { <실패 시 처리> }
try { <시도> } catch {|err| <err 레코드를 사용> }
try { <시도> } catch {|err| ... } finally { <항상 실행> }
```

| 요소 | 설명 |
| --- | --- |
| `try` 블록 | 오류가 날 수 있는 코드입니다. 이 블록은 일반 블록이라 바깥의 `mut` 변수를 바꿀 수 있습니다. |
| `catch` | 오류가 났을 때만 실행되는 클로저입니다. `{\|err\| ...}`로 오류 정보 레코드를 받습니다. |
| `finally` | 성공, 실패와 관계없이 마지막에 실행되는 정리용 클로저입니다. 반환값은 버려집니다. |
| 전체 값 | 오류가 없으면 `try` 블록의 값, 오류가 있으면 `catch` 블록의 값입니다. `catch`가 없고 오류가 나면 값이 없습니다(`nothing`). |

`catch`와 `finally`는 클로저이므로 바깥의 `mut` 변수를 바꾸거나 읽을 수 없다는 점에 유의하세요. 상태를 기록하려면 `try` 블록 안에서 갱신합니다.

### 예제 1: 오류를 무시하고 계속하기

```nu
try { error make { msg: 'Some error info' } }
print 'Resuming'
# => Resuming

try { ^nonexisting }
print 'a'
# => a
```

`catch`를 생략하면 오류가 조용히 삼켜지고 다음 문장이 실행됩니다. 존재하지 않는 외부 명령도 같은 방식으로 처리됩니다. 오류 원인을 확인하지 않고 무시하는 방식이므로 정말 실패해도 괜찮은 작업에만 쓰세요.

### 예제 2: catch로 대체 값 돌려주기

```nu
try { 1 / 0 } catch { 'An error happened!' }
# => An error happened!

try { 1 / 0 } catch {|err| $err.msg }
# => Division by zero.
```

`try`가 표현식이므로 `catch`가 돌려준 값이 전체 식의 값이 됩니다. `err`는 오류를 설명하는 레코드이고, 가장 자주 쓰는 필드는 `msg`(오류 메시지)입니다. 전체 필드 목록은 `try { 1 / 0 } catch {|e| $e }`로 직접 확인해 보세요.

### 예제 3: 파일 열기 실패를 안내 메시지로 바꾸기 (실습 과제 2 기본형)

```nu
try {
    open does-not-exist.json
} catch {|e|
    print $"파일을 열 수 없습니다: ($e.msg)"
}
```

존재하지 않는 파일을 `open`하면 오류가 나고, `catch`가 그 메시지를 받아 사용자 친화적인 문장으로 출력합니다. 사용자에게는 원본 오류 대신 "무엇을 어떻게 하면 되는지"를 알려 주는 것이 좋습니다.

### 예제 4: finally로 정리 작업 보장하기

```nu
try { 1 / 0 } catch { 'caught' } finally { print 'cleaning up' }
# cleaning up
# => caught
```

`finally`는 성공, 잡힌 오류, 아직 전파 중인 오류, `return`, `break`, `continue`, `exit`로 인한 조기 종료 모두에서 실행됩니다. 임시 파일 삭제, 연결 닫기처럼 "어떤 경우에도 해야 하는 일"에 씁니다. `catch` 없이 `try`와 `finally`만 쓰면 오류는 억제되지 않고, `finally`가 실행된 뒤 오류가 그대로 전파됩니다.

### 예제 5: error make로 직접 오류 만들기

```nu
def check-age [age: int] {
    if $age < 0 {
        error make {
            msg: '나이는 음수일 수 없습니다'
            help: '0 이상의 정수를 입력하세요'
        }
    }
    $age
}

check-age 30
# => 30

try { check-age (-5) } catch {|e| print $e.msg }
# 나이는 음수일 수 없습니다
```

`error make`에 레코드를 넘기면 사용자 정의 오류가 발생하고, 호출하는 쪽의 `try`가 그것을 붙잡을 수 있습니다. `msg`는 필수이고, 나머지는 선택입니다.

| 필드 | 타입 | 용도 |
| --- | --- | --- |
| `msg` | string | 오류 메시지(필수) |
| `labels` | table | 코드의 특정 위치를 가리키는 라벨 목록. 각 라벨은 `text`와 `span`을 가집니다. |
| `help` | string | 해결 방법 안내 |
| `code` | string | 오류 식별 코드 |
| `url` | string | 참고 문서 주소 |
| `inner` | table | 원인이 된 하위 오류들(오류 연쇄) |

### 예제 6: 라벨로 오류 위치 가리키기

```nu
def check-range [x: int] {
    if $x < 0 or $x > 100 {
        error make {
            msg: '범위를 벗어났습니다'
            labels: [{ text: '0~100 사이여야 합니다', span: (metadata $x).span }]
            help: '값을 확인하세요'
        }
    }
    $x
}
```

`(metadata $x).span`은 호출 코드에서 `$x`에 해당하는 위치입니다. 오류가 이 위치를 밑줄과 함께 가리키므로, 어떤 인자가 문제인지 사용자가 바로 알 수 있습니다. 11단원에서 구조화된 에러 설계를 더 깊이 다룹니다.

### 예제 7: 오류를 감싸서 다시 던지기

```nu
try {
    error make 'foo'
} catch {|err|
    print 'We got an error that will be chained!'
    error make { msg: 'bar', inner: [$err] }
}
```

하위 오류를 `inner`에 담아 더 높은 수준의 오류로 감쌉니다. "설정 파일을 읽지 못했다" 안에 "파일이 없다"를 넣는 식으로 원인 추적이 가능합니다.

### 예제 8: 실패해도 반복을 이어 가기

```nu
mut ok = false
mut tries = 0
while (not $ok) and $tries < 3 {
    $tries = $tries + 1
    try {
        open data.json | get items | length | print
        $ok = true
    } catch {|e|
        print $"실패: ($e.msg)"
    }
}
```

`while` 본문과 `try` 블록은 일반 블록이므로 `$ok`와 `$tries`를 바꿀 수 있습니다. 반면 `catch` 클로저 안에서는 `$tries`를 읽을 수 없으니 출력 메시지에 시도 횟수를 넣고 싶으면 `try` 밖에서 처리해야 합니다.

### 오류 처리 판단 기준

- 실패를 무시해도 되면 `try`만, 대체 값이 있으면 `catch`, 반드시 정리가 필요하면 `finally`.
- 사용자 입력이나 외부 데이터의 검증 실패는 `error make`로 만들어, 호출하는 쪽이 `try`로 다룰 수 있게 합니다.
- `catch`에서 오류를 삼키기만 하면 원인이 사라지므로, 최소한 `$err.msg`를 출력하거나 `inner`로 감싸 다시 던집니다.
- 외부 명령이 실행되지 못한 경우는 `try`로 잡히지만, 실행은 됐으나 종료 코드가 0이 아닌 경우의 처리는 버전과 설정에 따라 다를 수 있어 9단원의 `complete`로 직접 확인하는 방식을 배웁니다.

## 9. 자주 하는 실수와 도구 선택 기준

6단원에서 막히는 지점은 대부분 "문장인가 표현식인가", "블록인가 클로저인가" 두 질문으로 설명됩니다. 아래 표는 증상에서 원인과 해결로 거꾸로 찾아가도록 정리했습니다.

### 증상별 진단표

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `Capture of mutable variable` 오류 | `each`, `where`, `reduce` 같은 클로저 안에서 `mut` 변수를 읽거나 바꿨습니다. | 누적은 `reduce`, 상태 갱신은 `for`, 읽기만 필요하면 `let`으로 고정합니다. |
| `for` 뒤에 파이프를 붙이면 파싱 오류 | `for`는 값이 없는 문장입니다. | 값을 이어서 쓰려면 `each`로 바꿉니다. |
| `for` 결과가 화면에 안 나옴 | 문장이라 값을 반환하지 않습니다. | `print`를 쓰거나 `each`로 바꿉니다. |
| `if` 결과가 `null` | `else`가 없고 조건이 거짓이었습니다. | 값을 쓸 때는 `else`를 반드시 붙입니다. |
| `reduce` 결과가 예상과 다름(뺄셈, 문자열) | 매개변수 순서를 `{\|acc, it\|}`로 잘못 썼습니다. | Nushell은 `{\|it, acc\|}`입니다. |
| `reduce` 결과가 `null` | 조건 분기에서 `$acc`를 돌려주지 않는 경우가 있습니다. | 모든 분기가 새 누적값을 돌려주게 합니다. |
| `each` 결과가 빈 리스트 | 본문의 마지막 식이 `print`라서 값이 없습니다. | 값을 내는 식으로 끝내거나, 의도가 출력이면 그대로 둡니다. |
| `par-each` 결과 순서가 뒤섞임 | 기본값은 입력 순서를 보장하지 않습니다. | `--keep-order`를 쓰거나 `sort`합니다. |
| 파이프 안에서 `$in`이 엉뚱한 값 | `$in`이 파이프 단계마다 다른 입력을 가리킵니다. | 본문 첫 줄에서 `let x = $in`으로 고정합니다. |
| 조건에서 타입 오류 | `if`의 조건이 bool이 아닙니다. | `$list \| is-empty`, `$n > 0`처럼 bool을 만드는 식으로 바꿉니다. |
| `catch` 안에서 mut 변수 오류 | `catch`는 블록이 아니라 클로저입니다. | 상태 기록은 `try` 블록 안에서 합니다. |

### 어떤 도구를 쓸까: 결정 표

| 하려는 일 | 선택 | 이유 |
| --- | --- | --- |
| 참/거짓 두 갈래, 서로 다른 변수의 조건 | `if` / `else` | 가장 단순하고 표현식이라 값으로 씁니다. |
| 한 값의 여러 경우, 레코드와 리스트의 모양 | `match` | 패턴과 가드로 의도가 한눈에 보입니다. |
| 항목마다 변환해 같은 개수(또는 필터링된 개수)의 결과 | `each` | 파이프 결과가 다음 단계로 흐릅니다. |
| 조건에 맞는 항목만 남기기 | `where` | 변환이 필요 없으면 `each`보다 의도가 분명합니다. |
| 여러 항목을 하나의 값으로 접기 | `reduce`, 또는 `math sum` 같은 전용 명령 | 클로저 안에서 누적을 표현하는 정식 방법입니다. |
| 항목마다 오래 걸리는 독립 작업 | `par-each` | 병렬 처리로 시간을 줄일 수 있습니다. 측정해서 판단하세요. |
| `mut` 변수 갱신, 출력, 파일 쓰기 같은 부수 효과 | `for` | 블록이라 바깥 상태를 바꿀 수 있습니다. |
| 횟수를 모르고 조건이 앞에 있는 반복 | `while` | 조건이 거짓이 되면 끝납니다. |
| 종료 조건이 반복 중간에 있거나 끝없는 작업 | `loop` + `break` | 종료 시점을 본문에서 직접 정합니다. |
| 실패 가능한 작업, 사용자 안내 | `try` / `catch` | 오류를 값처럼 다룰 수 있습니다. |

### 전용 명령이 있는지 먼저 찾기

반복 코드를 쓰기 전에 "이미 이름이 있는 일인가"를 확인하세요. 합계는 `math sum`, 최댓값은 `math max`, 중복 개수는 `uniq --count`, 정렬은 `sort-by`, 앞쪽 몇 개는 `first`처럼 전용 명령이 있습니다. `help commands`로 검색하는 습관은 1단원에서 익혔습니다. 직접 `reduce`나 `for`를 쓰는 것은 전용 명령이 없는 로직일 때입니다.

정리하면 선택의 순서는 "전용 명령 → `where`/`each`/`reduce`(파이프) → `for`/`while`(문장)"이고, 앞에서 해결되면 뒤로 가지 않습니다. 파이프 쪽이 짧고 값이 흐르기 때문입니다.

## 10. 실습 과제와 풀이

목차의 실습 과제 2개를 먼저 풀이하고, 이어서 이 단원의 개념을 점검하는 추가 과제 3개를 둡니다. 풀이를 보기 전에 직접 시도한 뒤 비교해 보세요.

### 과제 1: 1부터 100까지 3의 배수의 합을 reduce로 구하기

```nu
# 풀이 A: where로 거른 뒤 reduce로 합산
1..100 | where {|n| $n mod 3 == 0 } | reduce {|it, acc| $acc + $it }
# => 1683

# 풀이 B: reduce 하나로 거르기와 합산을 함께
1..100 | reduce --fold 0 {|it, acc|
    if $it mod 3 == 0 { $acc + $it } else { $acc }
}
# => 1683

# 검증: 전용 명령
1..100 | where {|n| $n mod 3 == 0 } | math sum
# => 1683
```

풀이 A는 "거르기"와 "접기"를 분리해 읽기 쉽습니다. 풀이 B는 한 번의 순회로 끝나지만 `else { $acc }`를 빠뜨리면 안 됩니다. 정답은 3의 배수 33개(3, 6, ..., 99)의 합 3 × (33 × 34 / 2) = 1683입니다. 세 방식의 결과가 같은지 직접 비교해 보세요.

### 과제 2: 존재하지 않는 파일을 open할 때 try/catch로 안내하기

```nu
def safe-open [path: string] {
    try {
        open $path
    } catch {|e|
        print $"'($path)' 파일을 열 수 없습니다. 경로를 확인하세요. [원인: ($e.msg)]"
    }
}

safe-open missing.json
# 'missing.json' 파일을 열 수 없습니다. 경로를 확인하세요. [원인: ...]
```

`catch` 안의 문자열 보간에서 일반 괄호는 식으로 해석되므로, 설명용 괄호 대신 대괄호를 썼습니다. 성공하면 파일 내용이 그대로 반환되고, 실패하면 `print`로 안내하며 반환값은 없습니다. 더 나아가 `error make`로 실패를 호출자에게 다시 전달하는 버전도 만들어 보세요.

### 추가 과제 1: match와 가드로 FizzBuzz

1부터 15까지 3의 배수는 `Fizz`, 5의 배수는 `Buzz`, 둘 다이면 `FizzBuzz`, 나머지는 숫자 그대로 돌려주세요.

```nu
1..15 | each {|n|
    match $n {
        $x if $x mod 15 == 0 => 'FizzBuzz',
        $x if $x mod 3 == 0 => 'Fizz',
        $x if $x mod 5 == 0 => 'Buzz',
        _ => $n
    }
}
```

가드 순서가 중요합니다. 15의 배수를 먼저 검사하지 않으면 3의 배수 분기가 먼저 맞아 `Fizz`만 나옵니다. 위쪽 분기가 아래쪽 분기를 가릴 수 있다는 `match`의 규칙을 확인하는 문제입니다.

### 추가 과제 2: mut 변수 오류를 세 가지 방식으로 고치기

아래 코드는 오류가 납니다. `reduce`, `for`, `math sum` 세 가지로 각각 고쳐 보세요.

```nu
mut total = 0
[10 20 30] | each {|n| $total = $total + $n }
```

```nu
# reduce
[10 20 30] | reduce --fold 0 {|n, acc| $acc + $n }
# for
mut total = 0
for n in [10 20 30] { $total = $total + $n }
$total
# 전용 명령
[10 20 30] | math sum
# 모두 => 60
```

7장의 "클로저는 mut를 붙잡지 못한다" 규칙을 직접 체험하는 과제입니다. 세 방식 중 가장 짧은 것이 무엇인지, 그리고 전용 명령이 없다면 무엇을 고를지 생각해 보세요.

### 추가 과제 3: 클로저 공장과 로그 집계

먼저 곱셈 클로저를 만들어 돌려주는 명령을 작성합니다.

```nu
def make-multiplier [k: int]: nothing -> closure {
    {|n| $n * $k }
}
let triple = make-multiplier 3
[1 2 3] | each {|n| do $triple $n }
# => [3, 6, 9]
```

다음으로 로그 줄의 수준별 개수를 세어 봅니다.

```nu
let logs = ['INFO start' 'ERROR disk' 'INFO ok' 'WARN slow' 'ERROR net']
$logs
| each {|line| $line | split row ' ' | first }
| uniq --count
# => value별 count 테이블 (INFO 2, ERROR 2, WARN 1)
```

첫 코드는 7장 예제 4의 `$greeting`처럼 클로저가 `$k`를 붙잡는다는 것을, 둘째 코드는 전용 명령(`uniq --count`)과 `each`를 조합해 `for` 없이 집계할 수 있다는 것을 보여 줍니다. 여러 파일의 로그를 읽는 실제 버전은 10단원 종합 프로젝트에서 다룹니다.

## 11. 정리와 다음 단계

6단원을 한 문장으로 줄이면 "값이 흐르는 곳에는 표현식과 클로저를, 상태를 바꾸는 곳에는 문장과 블록을"입니다. `if`, `match`, `try`, `each`, `reduce`는 값을 돌려주므로 변수와 파이프에 연결하고, `for`, `while`, `loop`는 `mut` 변수를 갱신하는 부수 효과에 씁니다. 클로저가 `mut`를 붙잡지 못하는 규칙은 `reduce`와 `for` 중 하나로 풀면 되고, 실패는 `try`/`catch`로 다루되 `error make`로 의미 있는 오류를 직접 만들 수 있습니다.

### 스스로 점검하기

- `if`에 `else`가 없을 때 조건이 거짓이면 무엇이 반환되는가.
- `reduce`의 클로저 매개변수 순서는 무엇이며, `--fold`를 생략하면 초기값은 무엇인가.
- `for`가 파이프에 연결되지 않는 이유와 `each`가 `mut` 변수를 바꿀 수 없는 이유를 각각 한 문장으로 설명할 수 있는가.
- `catch`와 `finally`가 블록이 아니라 클로저라는 사실이 코드에 어떤 제약을 주는가.

### 다음 단원과의 연결

7단원에서는 JSON, CSV, YAML 같은 데이터를 읽어 오는데, 파일이 없거나 형식이 잘못되었을 때 이 단원의 `try`/`catch`가 바로 쓰입니다. 8단원에서는 `def`로 만드는 커스텀 명령어에 이 단원의 `if`, `match`, `error make`를 넣고, 클로저를 인자로 받는 명령도 만듭니다. 12단원에서는 `par-each`와 `generate`, `scan` 같은 고급 반복 도구를 `timeit`으로 비교합니다.
