# cmd는 같은 줄을 여러 번 읽는다

bash는 셸이 따옴표, 변수, 글롭(`*.txt`)를 모두 처리한 뒤 완성된 인수 목록을 프로그램에 전달합니다. 프로그램은 전달받은 인수에 따옴표가 있었는지조차 모릅니다.

cmd는 다릅니다. 이는 명령줄 문자열 전체를 그대로 프로그램에 넘기고, 그 문자열을 각각의 인수로 쪼개는 일은 각 프로그램이 스스로 해야 합니다. 대부분의 프로그램은 C런타임(CRT)이나, `CommandLineToArgvW`라는 윈도 함수를 통해 쪼갭니다. cmd가 그 앞에서 하는일은 고작, 'cmd 자신에게 의미있는 특수문자 처리' 밖에 없습니다.

| 단계      | 하는일                                       | 문자                 |
| :------ | :---------------------------------------- | :----------------- |
| 퍼센트 확장  | `%var%`, `%1` 등 처리                        | `%`                |
| 특수문자 파싱 | 따옴표 추직, `^`이스케이프 제거, 파이프/리디렉션 문자로 명령 분리 등 | `" ^ & \| < > ( )` |
| 지연 확장   | `!var!` 처리                                | `!`                |
| 실행      | 프로그램에 문자열 전달, 프로그램이 자체 규칙으로 argv 분해       |                    |

이 순서가 중요한 이유는 앞 단계에서 사용되어 사라진 문자는 뒤 단계로 전달되지 않기 때문입니다. 예를 들어 `%` 는 첫 단계에서 먼저 처리되므로, 2단계 이후부터는 존재하지 않습니다. 즉 `^%`으로 퍼센트 문자를 이스케이프로 보호할 수 없습니다. `!` 문자는 3단계에서 처리되므로  2단계에서 `^!`으로 한 번 보호했더라도 3단계에서는 한 번 더 보호가 필요할 수 있습니다. 이 구조를 알면 이스케이프 규칙들이 외울 것이 아니라 "예측 가능한 것"이 될 수 있습니다. (그럼에도 불구하고 규칙이 너무 지저분합니다.)

***

### 작은 따옴표는 cmd에서 아무런 의미가 없다.

가장 먼저 바로 잡을 오해입니다.  cmd에서 작은 따옴표는 그냥 글자입니다. 따옴표로 묶는 규칙도 존재하지 않습니다.

작은 따옴표가 예외적으로 의미를 갖는 부분은 `for /f` 명령의 `in (...)` 부분에서는 **이 안의 명령을 실행하고 그 출력을 읽는다**로 해석되는 의미를 가집니다. 다만 이것은 따옴표의 문법적 특성이라기보다는 for /f  명령의 고유 문법으로 봐야 합니다.

<br />

| 송장번호        | 수취인        | 국가 | 중량(kg) | 배송사       | 상태   |
| :---------- | :--------- | :- | :----- | :-------- | :--- |
| TX2410-0001 | 김민수        | US | 1.2    | FedEx     | 배송중  |
| TX2410-0002 | Emily Chen | SG | 0.45   | Ninja Van | 배송완료 |
| TX2410-0003 | 박서연        | JP | 2.8    | Yamato    | 통관대기 |
| TX2410-0004 | Tan, Wei   | MY | 0.9    | J\&T      | 배송중  |

### 큰 따옴표

큰 따옴표는 유일하게 의미있는 따옴표이며, 두 계층에서 동시에 다른 의미를 가질 수 있습니다.

<br />

먼저 따옴표 안에서는 `& | < > ^ ( )`가 특수 기능을 잃고 평범한 문자로 취급됩니다. 다만 `%` 만큼은 따옴표 안에서도 여전히 확장되고, 지연 확장을 켰다면 ! 도 마찬가지 입니다.

```
- 송장번호: TX2410-0001
  - 수취인: 김민수
  - 국가: US
  - 중량(kg): 1.2
  - 배송사: FedEx
  - 상태: 배송중
- 송장번호: TX2410-0002
  - 수취인: Emily Chen
  - 국가: SG
  - 중량(kg): 0.45
  - 배송사: Ninja Van
  - 상태: 배송완료
- 송장번호: TX2410-0003
  - 수취인: 박서연
  - 국가: JP
  - 중량(kg): 2.8
  - 배송사: Yamato
  - 상태: 통관대기
- 송장번호: TX2410-0004
  - 수취인: Tan, Wei
  - 국가: MY
  - 중량(kg): 0.9
  - 배송사: J&T
  - 상태: 배송중
```

프로그램의 인수 분해기는 공백을 나뉜 조각을 따옴표로 묶어 하나의 인수로 만듭니다. 이 때 따옴표 문자는 보통 argv에서 제거됩니다.

<br />

그리고 중요한 문제하나, 따옴표를 벗기는 것은 외부 프로그램의 역할입니다. `echo "a & b"`에서는 두 가지를 주목해야 합니다.

1. `&` 이 따옴표 내부에 있어서 보호받습니다. 두 개의 구문이 아닌 하나의 구문으로 처리됩니다.
2. `echo`는 내장 명령이기 때문에, 따옴표를 제거하는 CRT를 타지 않습니다. 따라서 echo에서는 따옴표가 그대로 노출됩니다.

<br />

따옴표는 등장할 때마다 on/off 이고, 홀수인 경우 끝까지 따옴표로 내부로 간주됩니다.

<br />

따옴표의 이스케이프는 누구에게 이스케이프하기 위한 것인가에 따라 다릅니다.

<br />

1. 프로그램에서 문자열 내부의 따옴표는 `\"`을 사용합니다.  그러나, cmd는 이것을 별개 의 두 개 문자로 인지합니다.
2. cmd 자신은 `^"`을 토글 없는 따옴표로 인식합니다.
3. `""` : 이중 겹따옴표는 일부 프로그램에서 리터럴 따옴표로 해석될 **수 있습니다.**

<br />

문제는 `\"` 을 읽는 주체가 매번 다르다는 점입니다. 프로그램은 리터럴 따옴표로 읽지만, cmd는에서는 따옴표 기능이 그대로 인식됩니다. 즉,

```
prog.exe "say \"hi\" & calc"
         ^^^^^^^
                ^^^
                   ^^^^^^^^^
```

<br />

만약 `&` 문자가 cmd 규칙에서 따옴표 외부(토글 off) 상태에 놓여있다면 파이프로 작동하면서 의도한 대로 움직이지 않게 됩니다.

따라서,

<br />

<br />

1. 가능하면 인수에 큰 따옴표 문자가 들어가지 않도록 설계합니다.
2. 불가피한 경우, 해당 프로그램이 어떤 방식으로 따옴표를 처리하는지 미리 확인합니다.
3. 신뢰할 수 없는 입력이 섞인다면, cmd 한 줄이 아니라 powershell이나 다른 언어로 넘어갑니다.

```python
def is_prime(n: int) -> bool:
  if n < 2:
    return False
  if n % 2 == 0 or n % 3 == 0:
    return False
  if n < 10:
    return True
  k, l = 5, int(n ** 0.5 + 0.5)
  while k < l:
    if (n % k == 0) or (n % (k + 2) == 0):
      return False
    k += 6
  return True
```
