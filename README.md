# md-works

Milkdown(Crepe) + Svelte 5 기반 **글쓰기용 Markdown 에디터**. [md-notes](../notes) 를 포크해 글감함·이력·코멘트 스레드·번들 백업 같은 집필 기능을 얹었다. 같은 소스에서 두 가지로 빌드한다.

| | 서버 버전 | 스탠드얼론 단일 HTML |
|---|---|---|
| 빌드 | `npm run build` → `dist/` + `server.js` | `npm run build:html` → `dist-html/md-works.html` |
| 글 | 루트 폴더의 `.md` 트리(열기·생성·이름변경·삭제·저장, 하위 폴더) | IndexedDB 에 여러 개 보관(폴더 없음). 열기·드롭·붙여넣기는 항상 새 글, `.md` 내보내기 |
| 이미지 | 글 옆 `assets/<글 이름>/` 파일 또는 Base64(설정 + 글별 변환) | IndexedDB Blob(`idb:<id>` 참조), 내보낼 때 Base64 로 되돌림 |
| 부가 데이터 | 노트 폴더의 `.works/`·`.comments/` 사이드카가 정본 | IndexedDB 가 정본 |
| 저장 | Ctrl+S + 자동 저장 기본 ON(입력 0.7초 후, 최대 10초) | 항상 자동 저장(입력 400ms 후, 탭 숨김·닫힘 시 즉시) |

`__MODE__`('server' | 'html') 빌드 상수로 셸(`ServerShell`/`StandaloneShell`)을 동적 import 해 쓰지 않는 모드의 코드는 번들에서 빠진다. `__PWA__`(boolean)는 `build:static` 에서만 true 이며, 서비스 워커 등록 코드(`src/lib/pwa/register.ts`)가 다른 빌드에서는 통째로 제거된다.

## 실행

```bash
npm install
npm run build
node server.js [루트폴더] [--port 5273] [--templates 템플릿폴더]   # 또는 npm start
```

- 정적 웹앱은 `npm run build:static` 후 `dist-static/` 폴더를 정적 호스팅(GitHub Pages, nginx 등)에 올린다. 스탠드얼론 단일 HTML 과 같은 기능(IndexedDB 저장)이며 파일이 여러 개이고 상대 경로(`./`)라 하위 경로에도 올릴 수 있다. `file://` 더블클릭으로는 열리지 않으므로 HTTP(S)로 제공한다.
- 정적 웹앱은 오프라인 설치(PWA)를 지원한다(`src/lib/pwa/`). HTTPS(또는 localhost)로 제공하면 브라우저가 설치를 제안하고, 첫 방문 후에는 네트워크 없이도 열린다.
  - `manifest.webmanifest` 와 `sw.js` 는 `npm run build:static` 이 빌드 때 생성하며 서버 빌드와 단일 HTML 에는 들어가지 않는다.
  - 새 버전은 자동으로 바꾸지 않고 "새 버전이 있습니다 — 새로 고침" 토스트를 눌렀을 때만 적용한다.
  - 다른 출처(pandoc 엔진, 텔레그램)는 서비스 워커가 가로채지 않으므로 docx·HTML·EPUB 내보내기의 엔진 내려받기는 첫 1회 온라인이 필요하다.
  - 아이콘은 SVG 뿐이라 iOS 홈 화면 등 일부 환경에서는 기본 아이콘으로 보일 수 있다.
- 단일 HTML 은 `npm run build:html` 후 `dist-html/md-works.html` 을 더블클릭으로 연다(서버 불필요). 저장소 루트의 `index.html` 은 개발 서버용 진입점이다.
- 개발: `NOTES_ROOT=<폴더> npm run dev`(Vite 개발 서버에 같은 API 가 붙는다, 포트 5273, `127.0.0.1`).
- docx 변환용 pandoc 엔진은 서버가 `node_modules/pandoc-wasm` 의 wasm 을 직접 제공한다(`GET /api/pandoc.wasm`). 실행 환경에도 `node_modules` 가 필요하다.

### 환경변수 (`.env.example` 참고)

우선순위: CLI 인자 > 실제 환경변수 > 앱 폴더의 `.env.production` > `.env`(`npm run dev` 는 Vite 규칙에 따라 `.env`·`.env.development`). 상대 경로는 서버를 실행한 폴더 기준.

| 변수 | 읽는 곳 | 의미 | 기본 |
|---|---|---|---|
| `NOTES_ROOT` | `server.js`, `vite.config.ts` | 노트 루트 폴더(CLI 첫 위치 인자가 우선) | 현재 폴더 |
| `NOTES_TEMPLATES` | 같음 | docx 템플릿 폴더(`--templates` 우선) | 앱 폴더의 `templates/` |
| `PORT` | `server.js` | 포트(`--port` 우선) | 5273 |
| `VITE_BUNDLE_KEY` | `src/lib/bundle/crypto.ts` (빌드 시 주입) | 번들 암호화 키. **빌드 때 코드에 박힌다** | 없음 |
| `WORKS_ALLOWED_HOSTS` | `server/api.js` | 기본(`127.0.0.1`·`localhost`·`[::1]`) 외에 허용할 Host 이름, 쉼표 구분(포트 제외). 역프록시용 | 없음 |

`VITE_BUNDLE_KEY` 가 비면 빌드 키 암호화(`MWB1`)·자동 백업의 암호화·텔레그램 올리기를 쓸 수 없고, 내보내기는 평문 zip 이나 비밀번호 암호화(`MWB2`)만 된다. 키를 바꾸면 이전 키로 만든 `MWB1` 파일은 새 빌드에서 열 수 없다(`MWB2` 는 키와 무관).

## 기능 개요

- **글 목록(왼쪽 사이드바)**: 서버·단일 모드가 같은 트리 UI를 쓴다. 단일 모드도 폴더를 가진다(글의 `folder` 필드, 빈 폴더는 따로 보관). 폴더는 접고 펼 수 있고(접힘 상태 저장), 항목을 더블클릭하면 그 자리에서 이름을 바꾸고 우클릭 메뉴로 이름 변경·삭제(·새 문서/폴더)를 한다. 항목을 끌어 다른 폴더로 옮기고(접힌 폴더 위에 잠깐 두면 펼쳐진다), 빈 곳에 놓으면 최상위로 간다. 정렬 아이콘 팝오버에서 이름순/최근 수정순/직접 정렬을 고르며, 직접 정렬은 폴더별 순서를 이 브라우저에만 저장한다(번들에는 싣지 않는다). 파일명 찾기는 일치 부분을 강조한다(초성 가능). 번들의 글 이름은 `폴더/이름.md` 경로라 서버↔단일 왕복에서 폴더가 유지되고, 이미지는 글이 있는 폴더 안의 `assets/<글 이름>/` 에 놓인다(옛 `폴더 - 이름` 으로 합쳐 가져온 글은 그대로 둔다). 전체 검색은 코멘트 내용도 찾는다.
- **표 도구**: 본문의 표에 마우스를 올리면 `확대 · 복사 · ⋯` 세 단추만 뜬다(우클릭도 같은 메뉴). `복사`는 설정의 '표 복사 기본 형식'(TSV 기본, CSV 선택)으로 복사하고, `⋯` 에서 HTML 서식·HTML 소스·아스키 표(`+---+`, 한글 폭 보정·숫자 열 오른쪽 맞춤)·마크다운 표로 복사하거나 CSV/TSV 파일로 저장하고 첫 행 헤더를 켠다/끈다. `확대`는 큰 창에서 머리글 정렬(숫자는 크기순)·표 안 찾기·열별 필터(`글자`, `>10`, `<=5`, `=값`, `!=값`)·열 이동을 하고, 칸을 누르거나 끌어(Shift+클릭, 열 선택 단추) 선택하면 개수·합계·평균·최솟값·최댓값·중앙값·분산·표준편차(모집단)를 보여 준다. 복사·저장은 지금 보이는 상태(필터·정렬·열 순서) 그대로 나가고, `문서 표에 반영`은 그 상태로 문서의 표를 바꾼다(숨긴 행은 삭제, 셀 서식은 일반 글자로 — 확인 후).
- **오른쪽 사이드바**: 본문 옆에 두고 보는 자료(글감·목차·코멘트·링크 탭). 상단바의 패널 버튼으로 열고 닫고, 왼쪽 가장자리를 끌어(또는 방향키·더블클릭 초기화) 폭을 조절한다(260~720px, 저장됨). 왼쪽 사이드바는 파일·검색만 둔다. 모바일은 하단 시트 하나만 열린다.
- **글감함(포스트잇)**: 오른쪽 사이드바 '글감' 탭. 입력창은 노란 메모지(기본 높이 220px)이고 Enter 로 붙인다(전송 버튼 없음, 터치 폭에서만 '글감 담기' 글자 버튼). 글은 .md 하나이고 글감은 전역 보관함에 쌓인다. 글에는 '핀'을 꽂고 떼는 것으로만 연결한다(글에 메모지를 꽂아 두는 느낌, 핀이 꽂힌 카드는 모서리에 핀이 보인다). 텍스트·이미지 붙여넣기. 별도 원전 칸은 없고 본문에 마커 줄을 쓴다(본문은 쓴 그대로 저장하고 카드를 그릴 때만 해석): `# 제목`(처음 나온 한 줄이 글감 제목), `@출처 https://…`(원전, 글자만·URL만·둘 다 가능), 줄 전체가 URL이면 원전 링크(`@` 줄과 URL 줄을 합쳐 첫 번째만 인정하고 나머지는 본문 글자로 남는다. 제목도 첫 번째만), `> 인용`(발췌). 본문 중간의 URL·`#태그`는 건드리지 않는다. 옛 글감의 원전 필드는 그대로(배지로) 보이고, 수정하면 마커 줄로 풀려 보인다. 보기 3종('이 글에 꽂힌 글감'/'모든 글감'/'휴지통')은 도구 줄의 아이콘 하나를 눌러 '아이콘+설명' 팝오버에서 바꾸고, 찾기는 돋보기 팝오버의 입력 하나다(본문에서 문장을 고르고 `Ctrl+Alt+G` 를 누르면 같은 입력이 '관련도순' 모드로 열린다). 새 글감과 글감 수정은 Enter 로 저장한다(Shift+Enter 줄바꿈, Esc 취소). 색 라벨 6종과 색 필터·일괄 색 변경은 설정의 '글감 색 사용'(기본 꺼짐)을 켰을 때만 나타나고, 꺼 두어도 이미 지정한 색은 카드에 보인다. 색 선택은 팝오버로 연다. 비슷한 글감 제안(한글 단어 + 문자 2-gram BM25), 본문에서 문장을 선택하면 뜨는 '글감 담기' 버튼(또는 `Ctrl+Alt+S`)으로 글감함에 담는다. 글감을 본문으로 보내는 기능은 만들지 않는다(원문·메모를 그대로 본문에 쓰지 않으므로 복사·붙여넣기로 충분).
- **글감 정렬·선택·일괄 작업**: '이 글에 붙은 것' 보기에서는 글별 순서(`orders[글]`, 작을수록 위)로 보이고, 카드를 끌어 다른 카드 사이에 놓으면(삽입 표시선) 순서가 바뀐다. 새로 붙이는 글감은 그 글의 맨 위에 놓이고, 순서를 바꾸면 바뀐 글감만 `updatedAt` 이 갱신된다(번들 병합이 글감 단위라 다른 기기와 합쳐도 순서가 통째로 뒤집히지 않는다). '전체'·'휴지통'·문구 찾기·검색어/색 필터가 걸린 상태에서는 순서를 바꿀 수 없다(필터를 풀면 가능). 선택은 `Ctrl`(Mac `Cmd`)+클릭(불연속 토글), `Shift`+클릭(연속 범위), 또는 도구 줄의 '선택' 버튼(체크박스 선택 모드, `Esc` 로 종료)으로 한다. 선택된 카드를 끌면 선택 전체가 상대 순서를 유지한 채 함께 움직인다. 선택 바의 기본 동작은 '핀 떼기'('이 글에 꽂힌 글감' 보기에서만)와 '삭제'(휴지통으로, 확인 없이 토스트, 복구 가능)이고, 색 변경(색 기능을 켠 경우)·'위로/아래로'(터치용)는 ⋯ 메뉴에 있다. 키보드: 카드에 포커스를 두고 `Alt+↑`/`Alt+↓` 로 한 칸 이동(선택이 있으면 선택 전체), 선택 모드에서 `Space` 로 선택 토글. 선택 상태는 저장하지 않는다.
- **글감 휴지통**: 하나뿐. 소프트 삭제(`deletedAt`) 후 복구하면 붙어 있던 글에 다시 붙는다. 완전 삭제는 묘비(`purged`)를 남겨 번들 병합이 되살리지 못하게 한다.
- **버전 이력**: 압축 저장. 24시간 이내는 전부, 이후 시간당 1개, 7일 초과는 일당 1개로 솎아낸다(이름 붙인 버전·최신 버전은 보존). 버전 간 diff(문단 단위 hunk) 후 hunk 선택 복구/전체 복구, 복구 직전 자동 스냅샷, 버전 이름 붙이기. 남기는 간격은 마지막 버전 후 5분. 이력 패널 위쪽의 검색 입력(대소문자 구분 토글, `Esc` 로 지우기)으로 지금 열린 글의 모든 버전에서 문구를 찾는다(정규식 없음, `src/lib/history/search.ts`). 일치하는 버전만 건수·발췌와 함께 최근순으로 남고, 현재 글에는 없고 과거 버전에만 있는 문구면 "지금 글에는 없는 문구입니다" 로 알린다. diff 보기에서는 검색어가 든 변경 구간으로 스크롤해 강조한다.
- **코멘트 스레드**: 본문 선택 → '코멘트'. 답글(messages 배열), 해결 표시, 위치 잃음 재부착, 스레드를 글감으로 보내기(코멘트는 글감으로 바뀐다). 원문 .md 는 바뀌지 않는다. 코드 블록 안에는 달 수 없다.
- **집필 보조**: 하단 상태 표시줄(글자 수 공백 포함/제외, 선택 글자 수, 글별 목표 분량 진행 막대), 집중 모드(타자기 스크롤). 폭 720px 이하는 사이드바가 하단 시트로 열린다.
- **집필 통계**: 상태 표시줄에 "오늘 +N자"(연속 작성 2일 이상이면 "· N일째")를 보이고, 누르면 통계 창(오늘·최근 7일·30일 합, 연속 작성일, 최장 연속, 최근 30일 막대 그래프, 최근 12주 잔디 표)이 열린다(`src/lib/stats/`, `StatsDialog.svelte`).
  - 하루 작성량은 그날 모든 글의 글자 수(공백 제외) 순증가이고, 한 번에 2,000자를 넘는 변화(붙여넣기·가져오기·버전 복구)는 세지 않는다. 기록은 이 기기에 400일치를 보관한다.
  - 폭 720px 이하에서는 표시줄의 표시가 숨고 명령 팔레트의 '집필 통계'(`view.stats`)로 연다.
- **편집/읽기**: 모든 글을 **편집 모드로 연다**. 읽기 모드는 상단 토글(`Ctrl+Alt+E`)로만 들어가고 글을 옮기면 편집으로 돌아온다.
- **디자인 설정**: 전역 하나(글별 없음). 본문 서체(시스템 설치 폰트 이름)·크기(12~24)·줄간격·자간, 문단 간격·첫 줄 들여쓰기·정렬(왼쪽/양쪽), 인용·코드·표·글감 인용, 제목 H1~H6 배율. 라이트/다크 팔레트 10색, 프리셋 5종(크림 기본·종이·세피아·밤·고대비) + 색별 조정, 대비 경고, JSON 내보내기/가져오기(스키마 검증). 번들에도 포함된다.
- **검색**: 문서 안(`Ctrl+F`), 파일 이름(부분 문자열 + 한글 초성), 전체 본문(`Ctrl+Shift+F`). 대소문자·정규식 옵션 공유. 서버는 인덱스 없이 워커 스레드에서 읽는다(8초, 전체 500건/파일당 50건/파일 2MB 이하). 이미지 검색 없음.
- **찾아 바꾸기**: 문서 안 찾기 막대에서 `Ctrl+H`(또는 ▸ 단추)로 '바꾸기' 줄을 펼친다(`src/lib/search/replaceText.ts`, `FindBar.svelte`).
  - '바꾸기'는 현재 일치 하나를 바꾸고 다음으로 가며, '모두 바꾸기'는 한 번의 실행 취소로 되돌아간다. 바꿀 말 입력에서 `Enter` 는 바꾸기, `Ctrl+Enter` 는 모두 바꾸기다.
  - 정규식 모드에서는 바꿀 말의 `$1`·`$&` 같은 캡처 참조를 쓰고, 일반 모드에서는 글자 그대로 넣는다. 읽기 모드에서는 비활성이다.
  - 전체 검색 패널의 '바꿀 말'(`replaceAll.ts`, `SearchPanel.svelte`)은 확인창을 거쳐 모든 글의 마크다운 원문을 줄 단위로 바꾼다. 펜스 코드 블록과 프런트매터는 건드리지 않고, 글마다 '바꾸기 전' 이름의 버전을 이력에 남긴다.
  - 서버 모드에서 검색 결과가 상한에 걸리면 일부 글만 바꾸므로 다시 실행해야 하고, 2MB 를 넘는 글은 대상에서 빠진다. 전체 바꾸기로 원문이 바뀐 글은 코멘트 위치가 어긋날 수 있다.
- **글 사이 링크**: 본문에 `[[글 이름]]`, `[[글 이름|표시 글자]]`, `[[폴더/글 이름]]` 을 쓰면 글끼리 연결된다(`src/lib/wikilink/`). .md 에는 이 문법이 글자 그대로 저장된다.
  - 대소문자는 구분하지 않는다. 경로가 일치하는 글이 먼저이고, 없으면 이름이 하나뿐인 글을 가리킨다. 같은 이름이 여러 개면 '모호'로 표시한다. 코드(펜스·인라인) 안은 링크가 아니다.
  - 있는 글은 링크 색 밑줄, 없는 글은 점선, 모호하면 경고색 물결선이다. 편집 모드에서는 Ctrl(Mac Cmd)+클릭, 읽기 모드에서는 클릭으로 연다(없는 글은 물어서 현재 글과 같은 폴더에 만든다).
  - `[[` 를 치면 글 이름 후보가 뜬다(↑/↓ 이동, Enter/Tab 선택, Esc 닫기, 한글 초성 가능).
  - 오른쪽 사이드바 '링크' 탭(`LinksPanel.svelte`)은 이 글을 가리키는 글(링크가 있는 줄의 문맥)과 이 글에서 가리키는 글을 보여 준다. 서버 모드는 전체 검색 API 로 찾으므로 결과가 상한에 걸리면 안내한다.
  - 글 이름 변경·이동(폴더 포함) 뒤에는 그 글을 가리키던 다른 글의 링크를 새 이름으로 함께 고친다. docx·HTML·EPUB 으로 내보낼 때는 표시 글자(없으면 글 이름)로 풀린다(`src/lib/export/prepare.ts`).
  - 한계: 같은 글에 `[글]: 주소` 정의가 있으면 `[[글]]` 이 참조 링크로 읽히고, 서버 모드 역링크는 줄 단위 검색이라 펜스 코드 블록 안을 구별하지 못한다.
- **가져오기·내보내기**: .md/.txt 붙여넣기, .md/.txt/.docx 드롭(서버는 선택 폴더에 생성, 같은 이름은 `이름 (2).md`), docx 내보내기(pandoc-wasm 워커, 템플릿 선택). 스탠드얼론은 docx 를 처음 쓸 때 pandoc 엔진(약 16MB)을 unpkg 에서 받아 IndexedDB 에 캐시한다(유일한 외부 요청, 단 텔레그램 올리기 제외). 받은 파일과 캐시에서 읽은 파일은 빌드 때 계산한 SHA-256 과 대조한다(`src/lib/pandoc/integrity.ts`, `wasmStore.ts`, `vite.config.ts` 의 `__PANDOC_WASM_SHA256__`). 캐시가 다르면 지우고 다시 받고, 새로 받은 것이 다르면 쓰지 않고 오류로 알린다.
  - **내보내기 형식**: ⋯ 메뉴 › 내보내기(명령 팔레트 포함)에서 .docx, HTML, EPUB 으로 내려받는다(`src/lib/export/`, `src/lib/docx-flow.ts`, `MoreMenu.svelte`). 'PDF로 저장(인쇄)' 은 브라우저 인쇄 창의 'PDF로 저장'을 쓴다(브라우저 안 pandoc 에는 PDF 엔진이 없다). HTML·EPUB 도 docx 처럼 pandoc-wasm 워커가 변환한다.
  - **HTML**: 파일 하나로 완결된다(이미지는 Base64, 수식은 MathML, 스크립트·외부 CSS·원격 글꼴 없음). 현재 디자인 설정과 보고 있던 테마를 담고, 인쇄할 때는 흰 배경이 된다. 글 속 `<script>`·`on*` 속성·`javascript:` 링크는 제거되고 문서의 CSP 도 스크립트를 막는다. 글에 직접 적힌 원격 이미지는 그대로 원격 주소를 가리킨다.
  - **EPUB**: 제목은 글 이름, 언어는 `ko`, 표지·목차는 pandoc 기본이다. 이미지는 파일 안에 포함되고, 디자인 설정 중 줄간격·문단 간격·들여쓰기·제목 배율만 담는다. 글 속 raw HTML 은 제외한다.
- **번들 백업·동기화**: 상단바 '백업'. 아래 참조.

### 번들 백업·동기화·텔레그램·서버 폴더 백업

- **번들** = 글·이미지·이력·글감·스레드·디자인을 담은 zip. 가져오기는 미리보기(추가/갱신/충돌 건수) 후 '병합 적용'. 같은 id 는 `updatedAt` 최신 우선, 이력·휴지통은 합집합, 글 본문이 양쪽에서 달라졌으면 진 쪽을 '병합 전' 이름의 버전으로 이력에 남긴다. 가져올 때 `now + 1일` 을 넘는 수정·삭제 시각은 현재 시각으로 자른다(시계가 앞선 기기의 번들이 이후 병합을 계속 이기지 않도록, `records.ts`). 평문 zip 은 CRC32 를 대조해 손상된 항목이 있으면 거부한다(`parse.ts`).
- **창 구성**: 상단바 백업 창은 탭 둘 — "내보내기·가져오기"(내려받기, 가져오기 미리보기·병합)와 "자동 백업"(서버 모드의 노트 폴더 백업·복원, 텔레그램, 알림 기준). 마지막 탭은 세션 동안 기억하고, 앱 창에 번들을 끌어다 놓으면 가져오기 탭이 열린다. 진행·성공·오류는 탭 아래 고정 영역에 보이고(`role=status`/`alert`), 창 밖에서 일어난 자동 백업의 실패만 토스트로 알린다. 병합 뒤 글·목록·열린 편집기·글감 패널은 자동으로 다시 읽고, 코멘트가 바뀐 경우에만 새로 고침을 안내한다.
- **암호화**: `.mwb` 는 두 형식이며 앞 4바이트(매직)로 구분한다(`src/lib/bundle/crypto.ts`).
  - `MWB1`(빌드 키): `VITE_BUNDLE_KEY` → SHA-256 → AES-256-GCM. `.mwb` = `MWB1` + iv 12바이트 + 암호문·태그. 키는 앱 빌드에 들어 있어 같은 빌드를 가진 사람은 풀 수 있다(비밀번호 수준의 보호가 아님). 자동 백업(텔레그램 자동 올리기, 서버 폴더 자동 백업)과 텔레그램 수동 올리기는 이 방식만 쓴다.
  - `MWB2`(비밀번호): 백업 창 "내보내기"에서 '비밀번호로 암호화'를 골라 직접 내려받는 파일에만 쓴다. PBKDF2-HMAC-SHA256(기본 600,000회, 횟수는 헤더에 기록) → AES-256-GCM. `.mwb` = `MWB2` + salt 16바이트 + 반복 횟수(uint32 BE) + iv 12바이트 + 암호문·태그. 키 없는 빌드에서도 쓸 수 있고 확장자는 `.mwb` 로 같다.
  - 비밀번호와 유도한 키는 어디에도 저장하지 않으며, 비밀번호를 잊으면 복구할 수 없다. 틀린 비밀번호와 파일 손상은 구분할 수 없어 같은 안내를 낸다.
  - 가져오기는 어느 경로든 매직으로 판별하고, `MWB2` 면 백업 창 안에서 비밀번호를 묻는다.
- **알림**: 마지막 백업이 N일(기본 7, 3/7/14/끔) 넘었고 이후 변경이 있으면 버튼 점 배지 + 시작 시 토스트. 텔레그램 자동 올리기를 켜 둔 채 마지막 성공이 설정 간격의 3배(또는 24시간 중 큰 값)를 넘고 올릴 변경이 있으면 마찬가지로 점 배지를 띄운다(다른 경로의 백업이 성공해도 가려지지 않는다). 경로별(내보내기·텔레그램·폴더) 마지막 성공 시각과 마지막 실패(시각·이유)를 따로 기록해 창에 상시 표시한다. 번들을 만들기 전 준비(열린 글 저장) 중의 쓰기는 변경으로 치지 않지만, 번들을 읽는 동안 생긴 변경은 다음 백업 대상으로 남는다.
- **텔레그램**: Bot API `getMe`/`sendMessage`/`sendDocument` 로 **올리기만** 자동(기본 30분, 최소 5분, 변경이 있을 때만). 파일명 `md-works-YYYYMMDD-HHmm.mwb`. **큰 번들 분할**: 암호화 번들이 45MB 를 넘으면 `….mwb.001`, `.002` … 조각(최대 20개)으로 순서대로 올리고 caption 에 `i/n`·전체 크기·SHA-256 앞 12자를 적는다(헤더 없이 원본 바이트를 자른 것이라 `cat` 으로도 합쳐진다). 재시도는 429(`retry_after` 만큼, 최대 60초)·5xx·네트워크 오류만 1회(401·403·413 등은 즉시 실패)이고 단일 파일도 같다. 중간 조각이 실패하면 중단하고 어디까지 올라갔는지 알리며, 그 암호화 번들 바이트를 **메모리에** 보관해 백업 창의 **이어 올리기**로 남은 조각만 올린다(전체 SHA-256 대조, caption 형식 동일). IV 가 매번 달라 다시 만들면 조각이 달라지므로 같은 바이트를 보관 중일 때만 가능하고, 탭을 닫거나 새로 올리기를 시작하면 사라진다(IndexedDB 에는 저장하지 않음). 실패 뒤 바뀐 글은 이어 올린 번들에 들어 있지 않다. 자동 올리기는 연속 실패 시 다음 시도 간격을 2·4·8배(최대 6시간)로 늘리고 성공하면 되돌린다. 가져오기는 받은 파일을 앱에 끌어다 놓는 수동 방식이며 조각은 모두 한꺼번에 놓으면 번호순으로 이어 붙인 뒤 복호화한다(빠진 번호·중복·다른 백업의 조각은 오류로 안내). 토큰·chat_id 는 localStorage `works.telegram` 에만 있고 번들에 들어가지 않는다. **브라우저에서 api.telegram.org 직접 호출(CORS)은 실서버로 미검증**(코드는 fetch 를 주입한 모의 테스트만).
- **문서 휴지통(서버)**: `DELETE /api/file` 은 영구 삭제 대신 `<루트>/.works-trash/<id>/` 로 옮긴다(폴더는 비 .md 파일·.git 까지 통째로, 글은 assets/<글 이름>·코멘트·이력·스레드 함께). 응답 `{ok, trashId}`. `GET /api/trash`(`{items:[{id,path,name,type,deletedAt,docs}]}` 최근순), `POST /api/trash/restore {id}`(같은 이름이 있으면 `이름 (2).md`/`폴더 (2)` 로 비켜 복구하고 assets·링크·사이드카 키를 새 이름에 맞춤, 없는 상위 폴더는 재생성 → `{ok,path,type}`. 이력·스레드 이식이 실패하면 응답에 `warnings` 가 붙고 그때는 휴지통 항목을 남긴다), `DELETE /api/trash?id=`(개별) / `DELETE /api/trash`(비우기) → `{ok,removed}`. 30일이 지난 항목은 서버 시작·목록 조회 때 지운다. 휴지통 폴더는 다른 API 로 접근할 수 없다(403).
- **문서 휴지통(화면·스탠드얼론)**: 글·폴더를 지우면(트리·우클릭·선택 일괄·상단 메뉴) 확인 없이 휴지통으로 가고 토스트 "'이름' 을 휴지통으로 옮겼습니다 + 되돌리기"(8초)가 뜬다. 왼쪽 사이드바 파일 탭 맨 아래 '휴지통 (N)' 단추를 누르면 파일 탭 자리에 휴지통 보기(`TrashPanel`, 서버·스탠드얼론 공용, 모드별 구현은 `TrashCtl`)가 열리고 '← 파일 목록' 으로 돌아온다. 항목 복구·완전 삭제(확인창)·여러 개 선택·비우기(확인창), 30일 뒤 자동 삭제. 복구 때 같은 이름이 있으면 `이름 (2)`. **스탠드얼론 구현**: 글 레코드에 `deletedAt`(+폴더를 지울 때 묶음 id `trashId`)만 표시하는 소프트 삭제이고 폴더(빈 폴더 포함)는 kv `trashDirs` 에 기억해 복구하면 구조째 돌아온다. 휴지통 글은 목록·검색·명령 팔레트·번들 내보내기·이름 계산·저장 경로에서 없는 글이고, 이력·코멘트 스레드·이미지(이미지 정리 참조 포함)·글감 핀은 그대로 둔다. 핀·스레드·이력의 정리는 완전 삭제(또는 30일 경과, 앱 시작·휴지통 열 때 확인) 때에만 한다. 삭제 묘비는 휴지통으로 보낼 때 남기고 복구하면 걷는다 — 번들 가져오기에서 같은 이름의 글이 이 기기의 휴지통에 있으면 번들 쪽 수정 시각이 삭제 시각보다 나중일 때만 같은 id 로 되살려 덮고(이력·핀 유지), 아니면 휴지통에 둔다. 번들 내보내기에는 휴지통 내용을 싣지 않는다. 서버 모드는 위 API 를 쓰고, 핀(경로 키)은 복구 때 이름이 바뀌었으면 새 경로로 옮기고 완전 삭제 때 뗀다(그 경로에 다른 글이 있으면 건드리지 않는다).
- **서버 폴더 백업**: `POST /api/backup`(200MB 상한)이 `<루트>/.works-backup/md-works-YYYYMMDD-HHmmss[-n].<mwb|zip>` 로 저장. 보존 규칙: 최근 10개는 전부, 그 밖에는 최근 48시간은 시간당 최신 1개·최근 30일은 하루당 최신 1개(나머지 삭제). `GET /api/backups`(목록), `GET /api/backup/file?name=`. 자동 백업 기본 켬·15분, 변경이 있을 때만. 번들이 200MB(`FOLDER_BACKUP_LIMIT`)를 넘으면 올리지 않고 실패로 알린다.
- **서버 파일 API**: `POST /api/create` 는 이미 있으면 409. `POST /api/rename` 은 대상이 이미 있거나 `assets/<새 이름>` 이 이미 있으면 409 이고, 숨김(`.` 으로 시작) 경로는 400.

## 번들 형식 (`src/lib/bundle/api.ts`)

서버 노트 폴더 구조의 상위 집합이라 풀면 그대로 노트 폴더가 된다. 글 식별은 이름(서버는 경로).

```
manifest.json                       {schema:'md-works-bundle', version:1, createdAt, mode, app, historyLayout:2}
<경로>.md, assets/<문서명>/<n>.<ext>  글과 이미지
.works/docs.json                    {<글 이름>: {updatedAt}}
.works/versions/<글 이름>.json      글 하나의 이력 버전 레코드 배열(너무 크면 <글 이름>.2.json …)
.works/snippets/_/<id>.json
.works/threads/<글 이름>/<id>.json
.works/design.json                  serializeDesign() 결과
.works/tombstones.json              {docs:{<이름>:deletedAt}}  (현재 내보낼 때 항상 빈 값)
.works/stats.json                  {days:{<YYYY-MM-DD>:작성량}}  집필 통계(가져올 때 날짜별 큰 값 우선)
```

통계는 이 기기(localStorage)가 정본이라 서버 모드에서도 서버 폴더에 따로 두지 않는다. 옛 빌드는 모르는 `.works/stats.json` 을 무시한다.

**이력 배치**: 글 하나의 이력을 파일 하나(`.works/versions/<글 이름 %XX 이스케이프>.json`, 레코드 배열)에 묶는다. 버전마다 zip 항목을 만들면 항목 수 상한(fflate 가 zip64 를 지원하지 않아 65,535)에 걸려 글·버전이 많은 보관소의 백업이 통째로 실패했기 때문이다. 빈 이력은 파일이 없다. 묶음이 압축 전 50MB 를 넘으면 `<글 이름>.2.json`, `.3.json` … 으로 나눈다(항목 하나 상한 100MB). 읽을 때는 옛 배치(`.works/versions/<글 이름>/<id>.json`, 버전당 파일)도 지원하고, 두 배치가 섞여 있으면 같은 id 는 한 번만 쓴다. `manifest.version` 은 1 로 두고 `historyLayout: 2` 로 새 배치를 표시한다 — 옛 빌드는 더 높은 `version` 의 번들을 통째로 거부하지만, 모르는 `.works/versions/<글>.json` 항목은 무시하므로 옛 빌드에서도 글·글감·코멘트는 읽히고 이력만 빠진다. 새 번들을 풀어 서버 노트 폴더로 쓰면 글·글감·코멘트는 그대로 쓰이지만 이력은 서버 폴더 배치(버전당 파일)와 달라 앱에서 번들을 가져와 합쳐야 한다.

공개 함수: `buildBundle()`, `previewBundle(bytes)`, `applyBundle(bytes, {applyDesign?})`. 암호화는 호출자(`crypto.ts`)가 한다.

## 보안 메모

- 서버는 `127.0.0.1` 에만 바인딩한다.
- `/api/*` 는 Host 헤더가 허용 목록(로컬 3종 + `WORKS_ALLOWED_HOSTS`)에 없으면 403(DNS rebinding 방어). Origin 이 있으면 Host 와 같아야 한다.
- 루트 밖 경로는 symlink 해석까지 거부, 글은 `.md`·이미지 확장자만. 사이드카 파티션은 이스케이프 + 컬렉션 폴더 바로 아래 한 단계 검사. 깨진 퍼센트 인코딩 URL 은 400/500 으로 끝내고 서버는 죽지 않는다.
- 번들 암호화 키는 단일 HTML·번들 JS 에 포함되므로 **보안이 아니라 난독화 수준**이다. `.env` 는 gitignore 대상이다.
- 텔레그램 토큰은 localStorage 평문 저장이다. 외부 CDN·폰트 요청은 없다(pandoc 엔진 내려받기 예외).
- 서버 버전을 역프록시로 노출하는 구성의 안전성은 미검증이다(인증이 없다).

## 알려진 한계

- 글 삭제는 번들로 전파되지 않는다(`tombstones.json` 은 항상 비어 있다). 한쪽에서 지운 글은 동기화하면 되살아날 수 있다.
- 텔레그램: 암호화 번들이 45MB 를 넘으면 조각(최대 20개, 약 900MB)으로 올리며 그보다 크면 올릴 수 없다. 봇 다운로드 한도(20MB) 때문에 가져오기는 수동. CORS 동작 미검증.
- 비어 있는 새 origin 에서의 복원 제안은 코드에서 확인하지 못했다(미검증).
- 이력은 서버 모드에서 앱 밖에서 바꾼 파일 이름을 따라가지 못한다.
- 서버 버전은 외부 수정 충돌(mtime)을 검사하지 않는다.
- AI 연관 검색·claude-ex 동기화는 범위 밖이다(`SuggestProvider` 인터페이스만 둠).
- 검색 이동 위치는 마크다운 문법(링크 주소 등)만 일치한 항목이 있으면 한두 칸 어긋날 수 있다.
- 폰트는 시스템에 설치된 것만 쓴다(번들·호스팅 없음). 기본 `Pretendard Variable`, 없으면 시스템 폰트.
