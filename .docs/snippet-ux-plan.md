# 글감 UX 개선 계획

## 요약
글감을 찾고 읽는 일을 오른쪽 사이드바에서 큰 모달로 옮긴다. 기본 필터를 '모든 글감'으로 바꾼다. 긴 글감을 제대로 렌더해서 보고 큰 창에서 고친다. 읽기 모드에서 코멘트를 본문과 함께 보고 인쇄한다.

## 확정된 결정
| 항목 | 결정 |
|---|---|
| 사이드바 | 글감 탭에는 '이 글에 꽂힌 글감'(끌어서 순서 변경 포함)과 빠른 입력만 남긴다. 카드를 누르면 모달이 열린다. |
| 기본 필터 | 모달과 사이드바 모두 '모든 글감'으로 시작한다. |
| 긴 글감 | 모달에서 전체 마크다운으로 렌더하고, 모달 전체 높이의 편집창에서 수정한다. 카드 목록은 지금처럼 가벼운 미리보기를 유지한다. |
| 코멘트 표시 | 읽기 모드에 '코멘트 보기' 토글을 둔다. 본문 각주(숫자)와 구분하려고 코멘트는 `[C1]` 배지를 쓴다. |
| 코멘트 범위 | 열린 코멘트와 해결된 코멘트를 모두 보인다. 해결된 코멘트는 흐리게 보인다. |
| 인쇄 | 토글 상태를 따른다. 더보기 메뉴에 '코멘트 포함 PDF' 바로가기를 둔다. |

## 작업 1. 글감 보관함 모달
- 새 컴포넌트 `SnippetLibrary.svelte`를 만든다. 열림 상태는 `snippets/state.svelte.ts`에 둔다.
- 화면은 왼쪽이 검색·필터·목록, 오른쪽이 선택한 글감의 읽기·수정 영역이다. 모바일(720px 이하)은 목록과 상세를 화면 전환으로 나눈다.
- 검색, 색 필터, 보기 전환(전체·이 글·휴지통), 다중 선택, 핀 꽂기·떼기, 휴지통은 기존 `state.svelte.ts` 함수를 그대로 쓴다. 로직을 새로 만들지 않는다.
- 모달은 기존 `modal` 액션(Esc·포커스 트랩)과 `modalFx`를 쓴다. 여는 곳은 사이드바 카드, 명령 팔레트, 단축키다.
- 순서 변경은 사이드바의 '이 글에 꽂힌 글감'에서만 한다. 모달은 순서를 바꾸지 않는다.

## 작업 2. 기본 필터
- `sn.view`의 초기값을 `'doc'`에서 `'all'`로 바꾼다.
- 사이드바는 '이 글에 꽂힌 글감'을 보여 줘야 하므로 사이드바 전용 보기와 모달 보기 상태를 분리한다. 모달의 필터를 바꿔도 사이드바 목록은 변하지 않는다.
- 회귀 위험: 지금은 `canReorder()`가 `view === 'doc'`에 묶여 있다. 사이드바 상태를 분리하면서 이 조건을 사이드바 기준으로 옮긴다.

## 작업 3. 긴 글감 읽기·수정
- 읽기: 글감 본문을 마크다운으로 렌더한다. 이미 쓰는 마크다운 라이브러리가 있는지 먼저 확인하고, 없으면 읽기 전용 Milkdown 인스턴스 재사용을 우선 검토한다. HTML을 그대로 주입하지 않는다(XSS 방지).
- 수정: 모달 오른쪽 영역의 '편집' 단추로 전체 높이 textarea를 연다. Ctrl+Enter로 저장하고 Esc로 취소한다. Tab 들여쓰기는 기존 `tabIndent`를 쓴다. 저장하지 않고 닫으면 확인을 묻는다.
- 편집 중 다른 글감을 누르면 저장 여부를 묻는다.
- 제목(`# `)·원전(`@`)·인용(`> `) 표기는 기존 `parseSnippet`/`editableText` 규칙을 그대로 지킨다.

## 작업 4. 코멘트 포함 읽기·인쇄
- 읽기 모드에서만 '코멘트 보기' 토글을 보인다. 편집 모드에서는 숨기고 꺼 둔다.
- 본문: 코멘트 구간 뒤에 색을 입힌 `[C번호]` 배지를 붙인다. 번호는 문서 순서대로 매긴다. 위치를 잃은 코멘트는 본문 배지 없이 목록에만 넣는다.
- 문서 끝: 각주 정의 아래에 '코멘트' 절을 둔다. 번호별로 인용 구절, 코멘트, 답글을 보인다. 해결된 코멘트는 회색과 '해결됨' 꼬리표로 구분한다.
- 구현 방식은 `pmComments.ts`의 데코레이션에 배지용 위젯 데코레이션을 추가하고, 문서 끝 목록은 읽기 전용 DOM으로 붙이는 것이다. 문서 내용과 저장되는 마크다운은 건드리지 않는다.
- 인쇄: `printCode.ts`의 `buildPrintClone`이 만드는 사본에 배지와 코멘트 절을 포함한다. `app.css`의 인쇄 규칙이 지금은 코멘트 강조를 모두 지우므로, 토글이 켜진 경우에만 배지와 코멘트 절을 남기도록 예외를 둔다.
- 더보기 메뉴(`MoreMenu.svelte`)에 '코멘트 포함 PDF'를 추가한다. 이 메뉴는 토글을 임시로 켜고 인쇄한 뒤 원래대로 돌린다.

## 병렬 진행
- 작업 1·2·3은 같은 파일(`SnippetPanel`, `state.svelte.ts`)을 건드리므로 하나로 묶어 순서대로 진행한다.
- 작업 4는 코멘트·인쇄 파일만 건드리므로 작업 1~3과 병렬로 진행할 수 있다.

## 검증
- `npm run check`와 `npm test`를 실행한다. dev 서버는 건드리지 않고 `netstat -ano`로 가동 여부만 확인한다.
- 새 단위 테스트: 보기 상태 분리(사이드바와 모달), 기본값 `'all'`, 코멘트 번호 매기기와 위치 잃은 코멘트 처리.
- 수동 확인: 모달 열기·닫기, 긴 글감 렌더와 수정, 읽기 모드 토글, 인쇄 미리보기, 모바일 폭.

## 확인이 필요한 사항
- 마크다운 렌더 방식: 기존 라이브러리가 있는지 구현 첫 단계에서 확인한다. 새 의존성이 필요하면 추가하기 전에 알린다.
- 코멘트 답글: 현재 `Thread.messages`가 첫 메시지와 답글을 구분 없이 순서대로 담는다. 첫 메시지를 '코멘트', 나머지를 '답글'로 표시한다.
